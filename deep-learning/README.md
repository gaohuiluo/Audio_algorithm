# 深度学习基础与 PyTorch 工程实战 · 写给转型算法工程师的实战笔记

> 会用 PyTorch 搭个网络不难，难的是**心里有底**——知道张量每一维在装什么、显存为什么会炸、网络凭什么会"学会"、为什么语音降噪不能只看幅度、损失和优化器到底在较什么劲。这个系列接着[《信号与系统》](../signals_and_systems/README.md)往下走：把深度学习的核心机件**逐个拆开、落回语音场景**讲透，让你从"会调 API"变成"真懂它在干嘛"，为转做语音算法打下工程地基。

---

## 这个系列是什么

- **受众**：有音频/驱动背景、已经读完信号与系统系列（会 STFT、会读语谱图）、正从驱动工程师转型算法工程师的人。
- **前置**：懂采样、FFT、STFT、语谱图、幅度与相位、复指数。这些不再从头讲，直接当跳板用。
- **不是什么**：不是 PyTorch API 手册、不是论文综述、不做干涩的数学证明。
- **是什么**：一套"看得懂、能落地"的技术博客，每篇一个核心机件，直觉先行、代码兜底、工程视角贯穿。

---

## 写作风格与约束

全系列共同遵守的硬约束（与信号与系统系列一脉相承）：

### 1. 直觉先行，数学兜底
每个概念**先给物理/工程画面，再上公式**。公式只保留最核心那一个，出现时必须逐项翻译成人话。
> 例：反向传播先带你"顺着一条责任链往回问：是谁、错了多少"，等直觉建立了，链式法则才变得顺眼。

### 2. 所有例子锚定音频/语音
一律用语音降噪、回声消除、语音分离、说话人识别举例。**禁用图像分类猫狗、房价预测、鸢尾花这类通用 ML 教材例子**。张量的每一维都落到真实含义（`[B, C, F, T]` = 批次/通道/频率/帧）。

### 3. 比喻必须有解释力
只保留能**揭示机制**的比喻（梯度消失=悄悄话传了 100 个人已听不清、显存=有限的工作台、mask=给频谱蒙一层透光度不同的膜）。坚决去掉只换花哨说法、不推进理解的修辞。

### 4. 代码把公式变成可运行
用 PyTorch + NumPy 把概念跑出来，能直接运行、注释讲清每步。**张量操作后必打印 shape**——搞清每一维在装什么，是这个系列的教学重点。

### 5. 讲"为什么需要"，落到工程
重点是"工程中遇到什么问题、为什么要这个工具"。凡有条件就补一线视角：显存 OOM 的真实算账、实时推理的因果性红线、定点化对复数运算的影响、驱动层流式管线与训练批采样的差异。


## 阅读建议

按序号顺读。每篇都建立在前一篇的钩子之上：搞不清张量 shape，就理解不了显存怎么算账；不懂反传的责任链连乘，就看不透 RNN 的梯度消失；不明白幅度谱丢了相位，就不知道复数网络在救什么。顺着读，九篇下来你会发现——**任何一个复杂的语音模型，都不过是这九篇零件的重新组合。**
