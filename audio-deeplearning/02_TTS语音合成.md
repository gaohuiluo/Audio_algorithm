# 第 2 篇｜TTS 语音合成：先画一张梅尔画布，再照着念成波形

> 一句话核心直觉：合成和识别是对称的两件事——识别是"长音频 → 短文本"，合成是"短文本 → 长音频"，同样卡在长度对不齐（6 个字要撑成几百帧波形）。主流做法把它拆成两段：**声学模型**先把文字变成一张梅尔谱"画布"（该发什么音、每个音占几帧、音高多少），用一个**时长预测器**显式决定"每个音素分几帧画布"来解决对齐；**声码器**再把这张画布"照着念"成高保真波形。看懂"时长预测器怎么把文字撑开成帧"，就看懂了现代 TTS 的脊梁。

---

## 一、先把教材那套扔一边

上一篇我们走通了"音频 → 文字"，核心是对齐：音频帧多、文字少，CTC/RNN-T 想办法把它们对上。这一篇把箭头掉个头——**文字 → 音频**。你以为掉头会简单点？恰恰相反，这回是"少 → 多"：输入"今天天气不错"六个字（展开成音素也就十几个），输出却是一段 1.5 秒、几百帧的梅尔谱、再变成两万多个波形采样点。**信息要从极少凭空长成极多**，而且长出来的东西还得自然——音高要有起伏、停顿要在该停的地方、同一个字换个语气整条曲线都不一样。

为什么现代 TTS 几乎都拆成**两段**？因为"文字 → 波形"这一跳太大，中间卡一个所有人都看得懂的"接口"——**梅尔谱**（signals 系列讲过的那张时间-频率能量图）——能把难题切成两个各自可控的子问题：

```
文字/音素 ──►【声学模型】──► 梅尔谱 [B,80,T] ──►【声码器】──► 波形 [B, T*hop]
             该发什么音              （中间接口）           把谱照着念
             每个音多长
             音高/能量多少
```

- **声学模型**（前段）：管"内容和韵律"——发什么音、每个音多长、音高能量怎么走。它输出一张梅尔谱。
- **声码器**（后段）：管"保真度"——把梅尔谱这张低分辨率的"画布"还原成高采样率的真实波形，补回所有相位和精细纹理。

两段分开训、分开换，接口清晰。这一篇我们前段讲 **FastSpeech2**（非自回归 + 时长预测器），后段讲 **HiFi-GAN**（GAN 声码器），最后拿 **VITS**（端到端）作对比。

---

## 二、为什么是"非自回归"：先看自回归栽在哪

早期的声学模型（Tacotron2）是**自回归**的：梅尔谱一帧一帧生成，第 $t$ 帧要喂进去才能算第 $t+1$ 帧，中间用注意力去文字序列里找"现在该念哪个字"。它音质不错，但有三个要命的毛病：

1. **慢**。几百帧只能串行生成，一帧等一帧，没法并行，实时性差。
2. **曝光偏差**（exposure bias）。训练时每一步喂的是真实的上一帧，推理时喂的是自己上一步生成的（可能有误差）的帧——训练和推理的输入分布不一致，误差会**逐帧累积放大**。
3. **注意力对齐会跑飞**。靠注意力软对齐决定"现在念到哪个字"，一旦权重乱了，就出现**漏字、重复念、念到一半停住**——这和上一篇 AED 识别里注意力跑飞是同一个病。

> **关键认知**：自回归 TTS 的三个病，根子都在"用注意力隐式地、串行地决定对齐"。既然对齐这么容易出事，**那就别让网络去猜对齐——直接显式地告诉它每个音素该占几帧。** 这就是 FastSpeech2 的核心思想：用一个**时长预测器**取代注意力对齐，一次把所有帧并行算出来（非自回归）。

## 三、时长预测器与长度调节器：把文字"撑开"成帧

这是本篇的脊梁，慢慢讲。

### 3.1 问题重述

音素序列是 `[B, L, D]`——L 个音素、每个 D 维特征（L 是十几）。梅尔谱是 `[B, T, D]`——T 帧（几百）。要从 L 变到 T，就得知道**每个音素占几帧**。这个"占几帧"就叫**时长**（duration）。

### 3.2 长度调节器：按时长复制

假设我们已经知道了每个音素的整数时长，比如 L=3 个音素，时长是 `[2, 3, 1]`（第 1 个音素占 2 帧、第 2 个占 3 帧、第 3 个占 1 帧，合计 T=6 帧）。**长度调节器**（length regulator）干的事简单到意外——**把每个音素特征按它的时长复制那么多遍，拼起来**：

```
音素特征:   p0      p1      p2          (L=3, 每个 D 维)
时长:        2       3       1
            ↓        ↓       ↓
展开后:  p0 p0  p1 p1 p1  p2            (T=6 帧)
```

就这么简单。`[B, 3, D]` 配上时长 `[2,3,1]`，变成 `[B, 6, D]`。这个"复制"就是"给每个音素分配几帧画布"的比喻的字面实现——音素 p1 分到 3 帧画布，就把它的特征涂满这 3 帧。之后再用几层网络（Transformer/Conv）把这张展开后的帧级序列精修成梅尔谱。

> **关键认知**：对齐问题在这里被**彻底显式化**了。网络不再"猜"每帧对应哪个音素——时长直接规定了对应关系，而且是硬的、确定的。没有注意力跑飞的空间，所有帧还能一次并行算完。代价是：时长本身得有个地方来。

### 3.3 时长从哪来：训练靠"老师"，推理靠预测

- **训练时**：时长不是网络猜的，而是从一个**对齐老师**那里拿到的"标准答案"（ground-truth duration）——用一个预训练的对齐模型（或上一篇的 CTC/强制对齐）算出每个音素真实占了几帧。有了这份标答，长度调节器就能精确展开，整个声学模型并行训练。
- **推理时**：没有标答了，于是训练一个**时长预测器**（duration predictor）去学这份标答。它吃音素特征 `[B,L,D]`，给每个音素回归一个时长标量 `[B,L]`。因为时长是正数且跨度大（从 1 帧到几十帧），一般在 **log 域**回归、用 MSE 损失（预测 $\log(\text{duration})$，推理时 `exp` 再取整）。

这就是非自回归的精髓：**把"对齐"这件难事，离线交给对齐老师算成标答，在线用一个小回归器学回来**，于是生成时不用再串行地猜对齐。

### 3.4 不只是时长：variance adaptor

光有时长，声音会很"平"——没有抑扬顿挫。FastSpeech2 在时长之外，还并排预测两样**韵律变量**，合称 variance adaptor：

- **基频 F0**（音高）：每帧的音调高低，决定语气、升降调。
- **能量**（energy）：每帧的响度。

这两样也在训练时从真实音频抽出来当标答、各自训一个预测器，推理时预测出来、**量化后查一个嵌入表加回帧级特征**。逐项翻译为什么需要：时长管"节奏快慢"、F0 管"音调起伏"、能量管"轻重"——这三样凑齐，合成语音才有自然的韵律，而不是机器人念经。

## 四、声码器 HiFi-GAN：把梅尔画布念成波形

声学模型吐出的梅尔谱 `[B, 80, T]`（80 个梅尔频带、T 帧）还不是声音——它是一张低分辨率、而且**丢了相位**的"画布"。signals 系列讲过：梅尔谱只有幅度、没有相位，而相位携带着波形的精细结构。声码器的活就是：**从只有幅度的梅尔谱，生成出带正确相位、高采样率的波形**。一帧梅尔要变成 hop_length（比如 256）个波形采样点，`[B,80,T]` → `[B, 1, T*256]`，又是一个"少 → 多"的放大。

### 4.1 生成器：逐级上采样 + 多感受野融合

HiFi-GAN 的生成器是一串**转置卷积**（`ConvTranspose1d`）把时间轴逐级放大：比如 256 倍上采样拆成 8×8×2×2 四级，每级放大若干倍，直到时间长度从 T 变成 T×256。每级上采样后接一个**多感受野融合**（MRF）模块——几个不同卷积核大小、不同膨胀率的残差块并联相加。为什么要多感受野？因为语音同时有**长周期结构**（基频几百 Hz 的周期）和**短瞬态**（爆破音），不同核宽各管一段尺度，加起来才能同时还原粗细纹理。

### 4.2 判别器：专抓语音的"周期性"

GAN 要有判别器。HiFi-GAN 的判别器设计是它的点睛之笔，分两组：

- **多周期判别器**（MPD）：把一维波形按不同周期（2、3、5、7、11 这些质数）**折叠成二维**再卷积。为什么？语音是**准周期**信号——浊音的基频让波形每隔若干采样点就重复一次。把波形按周期 p 折叠，周期性结构就在二维上对齐暴露出来，判别器一眼能看出"这段的周期性真不真"。这是针对语音最本质的结构下的刀。
- **多尺度判别器**（MSD）：在原始、2 倍降采样、4 倍降采样三个尺度上分别判别，抓不同时间尺度的真假。

### 4.3 三个损失一起上

HiFi-GAN 训练时生成器的损失是三项加权和，逐项翻译：

- **对抗损失**：骗过判别器，让生成波形被判成"真"。
- **梅尔重建损失**：把生成波形重新算成梅尔谱，和输入的梅尔谱做 L1——保证"念出来的"内容和"画布"一致，这是稳住训练、不让 GAN 乱飘的关键锚。
- **特征匹配损失**：让生成波形在判别器各层的中间特征，去逼近真实波形的中间特征——一种更细的"像不像"约束。

> **关键认知**：GAN 声码器相比老式的自回归声码器（WaveNet 逐采样点生成）快几个数量级，根子在于**它一次并行生成整段波形**，没有"一个采样点等一个采样点"的串行链。质量能顶上去，靠的是"多周期判别器盯住语音的准周期结构 + 梅尔重建损失锚住内容"。

## 五、另一条路：VITS 端到端

两段式清爽，但有个结构性缺陷：**声学模型是照着"真梅尔"训的，声码器也是照着"真梅尔"训的，可推理时声码器吃到的是声学模型"预测的梅尔"**——两段在梅尔这个接口上存在训练/推理不匹配（和自回归的曝光偏差异曲同工）。

**VITS** 干脆把两段焊成一个端到端模型：文字直接到波形，中间的梅尔不再是硬接口，而是一个**隐变量**。它用了三样东西捏在一起——条件 VAE（把波形编码成隐变量再解码）、normalizing flow（让隐变量分布更灵活）、以及 HiFi-GAN 式的对抗训练；对齐则用一个**单调对齐搜索**在训练中自己找（不需要外部时长标答）。它还把时长做成**随机**预测器——同一句话每次合成的韵律略有不同，更像真人。

| | 两段式（FastSpeech2 + HiFi-GAN） | 端到端（VITS） |
|---|---|---|
| 训练复杂度 | 低，两段分开训，好调试 | 高，多个模块联合训，较难稳 |
| 训练/推理一致性 | 梅尔接口有不匹配 | 端到端，无中间接口失配 |
| 可控性 | 高（时长/F0/能量显式可调） | 中（韵律随机，细调不如显式） |
| 推理速度 | 快（都非自回归） | 快 |
| 韵律自然度 | 好 | 更自然（随机时长带来多样性） |

实践里两种都在用：要**强可控、好部署、分段换声码器**选两段式；要**端到端最自然、少维护接口**选 VITS 这类。

## 六、代码实战：长度调节器 + 时长预测器 + 上采样块

下面三段 CPU 可跑，串起 TTS 两段的三个核心零件。

### 6.1 长度调节器：按时长把音素撑成帧

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
B, L, D = 2, 4, 16          # 批 2, 每句 4 个音素, 每音素 16 维

phonemes = torch.randn(B, L, D)                 # 音素特征 [B, L, D]
durations = torch.tensor([[2, 3, 1, 2],         # 第 1 句各音素时长
                          [1, 1, 4, 2]])         # 第 2 句（和为 8，与上句一致便于成批）

def length_regulator(x, dur):
    """按整数时长复制每个音素，撑成帧级序列。"""
    out = []
    for b in range(x.size(0)):
        # repeat_interleave: 第 i 个音素特征沿时间复制 dur[i] 次
        expanded = x[b].repeat_interleave(dur[b], dim=0)   # [T_b, D]
        out.append(expanded)
    return torch.stack(out, dim=0)              # 这里各句 T 相同可直接 stack

frames = length_regulator(phonemes, durations)
print("phonemes:", phonemes.shape)              # torch.Size([2, 4, 16])
print("frames   :", frames.shape)               # torch.Size([2, 8, 16])  L=4 撑成 T=8
```

`[2,4,16]` 的 4 个音素，按时长 `[2,3,1,2]`（和为 8）被复制撑成 `[2,8,16]`——这就是"给每个音素分几帧画布"的字面实现。真实推理里各句时长和不同，要再做 padding 对齐，这里为演示让两句总帧数都=8。

### 6.2 时长预测器：log 域回归

```python
class DurationPredictor(nn.Module):
    """吃音素特征，给每个音素回归一个 log 时长。"""
    def __init__(self, d, hidden=32):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv1d(d, hidden, 3, padding=1), nn.ReLU(), nn.Dropout(0.1),
            nn.Conv1d(hidden, hidden, 3, padding=1), nn.ReLU(), nn.Dropout(0.1),
        )
        self.proj = nn.Linear(hidden, 1)        # 每个音素出 1 个标量

    def forward(self, x):                       # x: [B, L, D]
        h = x.transpose(1, 2)                   # -> [B, D, L]  conv1d 要通道在中间
        h = self.net(h)                         # -> [B, hidden, L]
        h = h.transpose(1, 2)                   # -> [B, L, hidden]
        return self.proj(h).squeeze(-1)         # -> [B, L]  每音素一个 log 时长

dp = DurationPredictor(D)
log_dur_pred = dp(phonemes)                     # [B, L]
print("log_dur_pred:", log_dur_pred.shape)      # torch.Size([2, 4])

# 训练：对着老师给的真实时长（log 域）做 MSE
log_dur_target = torch.log(durations.float() + 1e-5)       # [B, L]
dur_loss = F.mse_loss(log_dur_pred, log_dur_target)
print("duration loss:", dur_loss.item())
# 推理：exp 回时长、取整、下限 1
dur_infer = torch.clamp(log_dur_pred.exp().round(), min=1).long()
print("dur_infer:", dur_infer.shape, dur_infer.tolist())   # [B, L]
```

时长预测器就是个小 Conv 回归头，`[B,4,16]` → `[B,4]`，在 log 域对着老师标答训 MSE，推理时 `exp`→取整→下限 1 得到整数时长，喂给 6.1 的长度调节器。

### 6.3 声码器生成器的一个上采样块

```python
class UpsampleBlock(nn.Module):
    """HiFi-GAN 风格：转置卷积上采样 + 一个残差精修。"""
    def __init__(self, c_in, c_out, up=8):
        super().__init__()
        # 转置卷积：时间轴放大 up 倍（kernel=2*up, stride=up 是常用配法）
        self.up = nn.ConvTranspose1d(c_in, c_out, kernel_size=2*up, stride=up, padding=up//2)
        self.res = nn.Conv1d(c_out, c_out, kernel_size=3, dilation=1, padding=1)

    def forward(self, x):                       # x: [B, c_in, T]
        x = F.leaky_relu(self.up(x), 0.1)       # -> [B, c_out, T*up]
        x = x + self.res(x)                     # 残差精修，长度不变
        return x

mel = torch.randn(B, 80, 20)                    # 梅尔谱 [B, 80, 20 帧]
blk = UpsampleBlock(80, 64, up=8)
wav_feat = blk(mel)                             # -> [B, 64, 160]  时间放大 8 倍
print("mel     :", mel.shape)                   # torch.Size([2, 80, 20])
print("after up:", wav_feat.shape)              # torch.Size([2, 64, 160])
```

一级上采样把 20 帧放大成 160（×8）。真实 HiFi-GAN 把这种块串 4 级（如 ×8×8×2×2=256），最后一层 Conv1d 收到 1 个通道、过 `tanh`，就得到 `[B, 1, T*256]` 的波形。全部用真实 API：`ConvTranspose1d`、`repeat_interleave`、`mse_loss`，没有发明函数。

## 七、这在工程里解决什么问题

| 场景 | 选型 | 为什么 |
|---|---|---|
| 导航/客服/有声书等可控合成 | 两段式 | 语速、音高显式可调，声码器可单独升级 |
| 追求最自然、少维护 | VITS 端到端 | 无梅尔接口失配、随机韵律更像真人 |
| 端侧实时 TTS | 非自回归声学 + 小声码器 | 并行生成、无串行链，才能实时 |
| 多说话人 / 音色克隆 | 任一前段 + 说话人嵌入 | 把说话人向量（见第 4 篇声纹）加进条件 |

几个一线视角：
- **梅尔谱作接口的工程价值**：前后两段解耦，声码器能独立训练、独立换（HiFi-GAN 换 BigVGAN 不用动声学模型），还能复用——这是两段式至今不被淘汰的实际原因。
- **实时性**：非自回归是端侧 TTS 的命门。自回归逐帧/逐采样点的串行链在手机上根本跑不动，FastSpeech2 + HiFi-GAN 都并行，才有实时的可能。
- **可控性 vs 自然度**：显式时长/F0 可控但要调，随机时长自然但难精细控制——产品要"稳定可预期"选显式，要"像真人"选随机。
- **指标与听感背离**：梅尔重建损失低不代表好听（相位、韵律它不管），TTS 最终还得靠 MOS 主观打分（第 6 篇会提评估），这点和降噪里 PESQ 高未必听感好是同一个教训。

## 八、埋一个钩子

识别（第 1 篇）和合成（本篇）都是"大模型、离线或准实时"的活。但有一类场景完全不同：手机、耳机、音箱要**一直醒着**，24 小时听着，只为等你说出那一个唤醒词——它跑在最省电的小核上，容不得一个大模型。这种"常开、极省电、只认一个词"的检测该怎么设计？下一篇进入**语音唤醒 KWS**。

---

## 本篇小结

- **两段式骨架**：声学模型（文字→梅尔谱，管内容和韵律）+ 声码器（梅尔谱→波形，管保真度），中间用梅尔谱当清晰接口，分开训、分开换。
- **FastSpeech2 的脊梁**：用**时长预测器**显式决定每个音素占几帧、**长度调节器**按时长复制撑开成帧级序列，取代易跑飞的注意力对齐，从而**非自回归并行生成**；时长训练靠对齐老师给标答、推理靠 log 域回归学回来；再加 F0/能量补齐韵律。
- **HiFi-GAN 声码器**：转置卷积逐级上采样 + 多感受野融合生成器；多周期判别器专抓语音准周期结构 + 多尺度判别器；对抗 + 梅尔重建 + 特征匹配三损失。并行生成，比自回归声码器快几个数量级。
- **VITS 端到端**：焊掉梅尔接口、消除两段失配，VAE+flow+对抗，随机时长更自然；代价是训练复杂、可控性弱。
- **工程意义**：非自回归是端侧实时的命门；梅尔接口让两段解耦可换；可控性与自然度要按产品取舍；最终音质得靠 MOS 而非重建损失。
- **下一步**：从大模型转到"常开、极省电、只认一个词"的语音唤醒。
