# 第 3 篇｜语音唤醒 KWS：一个一直醒着、只认一个词的小网络

> 一句话核心直觉：唤醒词检测不是"识别一整句"，而是让一个**极小、极省电、一直醒着**的网络 24 小时盯着音频流，只回答一个是非题——"刚才那一小段里有没有出现'小爱同学'？"。它的全部难点不在准确率的上限，而在**约束**：几十 KB 的模型、毫瓦级功耗、严格因果（不能等你说完整句）、还要在"误唤醒"（没叫它却醒了）和"漏唤醒"（叫了没醒）之间精确拿捏一个阈值。看懂这套"小模型 + 流式后验平滑 + FAR/FRR 权衡"，就看懂了端侧常开检测的全部套路。

---

## 一、先把教材那套扔一边

前两篇都是"大活"：ASR 要把整句话转成文字，TTS 要合成一段自然语音——模型大、算力足、可以准实时甚至离线。这一篇的场景彻底反过来。

想象你手机/耳机/音箱里那个唤醒词检测器。它的处境是：

- **一直开着**。主芯片（CPU/NPU）大部分时间在睡觉省电，唤醒检测跑在一颗极低功耗的小核（DSP 甚至专用唤醒芯片）上，24 小时不停地听。
- **功耗预算是毫瓦级**。它要是费电，你的耳机续航就没了。所以模型只能有几十 KB、几十万次乘加/帧。
- **严格因果、低延迟**。你说完"小爱同学"，它得在一两百毫秒内醒过来，不能等一句话说完再判断。
- **几乎永远是负样本**。你一天跟音箱说十次话，但它听了一整天的环境声——绝大多数时间答案都是"没有唤醒词"。这个极端不平衡，是它和普通分类最不一样的地方。

> **关键认知**：唤醒词检测（KWS）和语音识别是两种生物。识别追求"把任意内容转对"，KWS 追求"在极紧的算力/功耗/延迟预算下，把一个固定的词从无穷无尽的背景声里可靠地拎出来"。它的设计全程被**约束**主导，而不是被精度上限主导。

传统做法又是 HMM/关键词-填充模型那套（keyword-filler），这一篇我们直接讲现代端侧 KWS 的主流形态：**一个 small-footprint 的小神经网络 + 流式后验平滑 + 一个精心调的判决阈值**。

---

## 二、模型：为什么是"小 Conv + 一点时序"

### 2.1 输入是什么

KWS 不吃原始波形，吃的是一小段**梅尔谱/MFCC**（signals 系列讲过）。典型做法：取最近约 1 秒的音频，算成 `[B, 1, F, T]`——比如 40 个梅尔频带（F=40）、约 100 帧（T=100）、单通道。唤醒词也就一秒上下，这个窗口刚好罩住一个词。

### 2.2 DS-CNN：用深度可分离卷积把参数压到极致

端侧 KWS 的经典骨干是 **DS-CNN**（深度可分离卷积网络）。它为什么不用普通卷积？因为普通卷积参数和算力都贵，而 KWS 的预算只有几十 KB。深度可分离卷积（3A 的 Conformer 篇里 depthwise 卷积讲过）把一次卷积拆成两步：

- **depthwise**：每个通道单独卷自己（`groups=通道数`），只管"每个频带内的局部时频图案"，参数极少。
- **pointwise**（kernel=1）：再用 1×1 卷积在通道间混合信息。

拆开后参数量大约降一个数量级，精度基本不掉——这正是它能塞进几十 KB 的根本。整个 DS-CNN 就是"一层普通卷积打底 + 几层 depthwise/pointwise 堆叠 + 池化 + 一个小全连接出分数"。

### 2.3 要不要时序记忆

有两种主流形态，各有取舍：

- **纯卷积（DS-CNN）**：把 1 秒窗口当一张图一次卷完，输出一个分数。简单、好量化、延迟固定。缺点是窗口外的历史它不记得。
- **卷积 + 轻量 RNN（如 CRNN，小 GRU）**：卷积抽局部特征，GRU 顺着时间维护一个状态，天然适配**流式**——来一帧更新一次状态、吐一个后验。缺点是 RNN 的状态在量化/部署时要小心（定点累积误差）。

> **关键认知**：KWS 模型的每一个结构选择，背后都是算力账。深度可分离卷积是为了省参数，纯卷积 vs 轻量 RNN 是在"实现简单好量化"和"天然流式省重复计算"之间选。没有"更先进就更好"，只有"在这个预算下哪个够用"。

## 三、流式：别每帧重算整段，也别信单帧

### 3.1 滑动窗口的重复计算陷阱

最朴素的流式：每来一帧，就把最近 1 秒重新喂进网络判一次。但相邻两次的窗口 99% 重叠——你在反复重算几乎相同的东西，功耗爆炸。工程上要么用**带状态的流式卷积/RNN**（只增量算新帧、复用历史，和 3A 讲的流式状态缓存一个思路），要么**每隔若干帧才判一次**（降低判决频率省电）。

### 3.2 后验平滑：单帧分数不可信

就算模型每帧（或每隔几帧）吐一个"是唤醒词"的后验概率 $p_t \in [0,1]$，你也**不能看到一帧 $p_t$ 冲高就立刻唤醒**——单帧概率抖动很大，一个尖峰很可能是噪声误触。标准做法是**后验平滑**：对最近一个窗口的后验做滑动平均，

$$ \bar{p}_t = \frac{1}{w}\sum_{j=t-w+1}^{t} p_j $$

逐项翻译：$\bar p_t$ 是平滑后的后验，$w$ 是平滑窗口帧数，就是把最近 $w$ 帧的瞬时后验求个平均，压掉尖峰毛刺。然后判决规则是：**平滑后验 $\bar p_t$ 连续超过阈值 $\tau$（或在一个窗口里累计超过），才算检测到唤醒词**。

> **关键认知**：唤醒词是一段持续约 1 秒的**连续**声音事件，真唤醒会让后验在一小段时间里**持续**高，而噪声误触通常只是**瞬间**尖峰。后验平滑 + "持续超阈"正是利用这个时间结构，把瞬间毛刺和持续事件区分开。这是单帧分类器升级成事件检测器的关键一步。

---

## 四、FAR 与 FRR：那个阈值 τ 怎么定

### 4.1 两类错误

判决阈值 $\tau$ 一旦定下，就会犯两类错，它们此消彼长：

- **误唤醒**（false alarm，FAR）：没人叫它，它自己醒了。指标常用"每小时误唤醒几次"（FA/hour）。用户体验上这个最招人烦——音箱半夜自己亮灯说话。
- **漏唤醒**（false reject，FRR）：你叫了它没醒。你得喊第二遍，体验也差。

$\tau$ 调高 → 更难触发 → 误唤醒少了，但漏唤醒多了（叫不醒）；$\tau$ 调低 → 反过来。**没有两全**，只能按产品取舍。

### 4.2 怎么权衡

工业界的标准做法是画 **DET 曲线**（或 ROC）：横轴 FAR、纵轴 FRR，扫过所有 $\tau$ 得到一条曲线。然后定一个硬约束——通常是**误唤醒率**（比如"每 24 小时最多误唤醒 1 次"，因为误唤醒最伤体验），在满足这个约束的前提下，选让漏唤醒最小的那个 $\tau$。

> **关键认知**：KWS 的"准确率"从来不是单一数字，而是**一条 FAR-FRR 权衡曲线**。产品定义会先钉死一个误唤醒上限（这是红线），再在红线下尽量压低漏唤醒。离开"误唤醒约束"谈唤醒率没有意义。

### 4.3 还有数据这关

唤醒词检测的难，一半在数据。正样本（有人说唤醒词）相对好收，难的是**负样本的多样性**——电视声、音乐、炒菜声、以及和唤醒词**发音相近的词**（"小爱"vs"小艾""小菜"）。这些"难负样本"（hard negatives）决定了误唤醒率。所以 KWS 数据工程的核心是**大量、多样、带难负样本的负集**，外加对正样本做远场/混响/加噪增广（因为用户往往在几米外、嘈杂环境里喊）。

## 五、代码实战：一个最小 DS-CNN 唤醒检测器 + 流式后验平滑

CPU 可跑。先搭一个深度可分离卷积的小网络，吃 `[B,1,40,100]` 的梅尔谱、出"是唤醒词"的二分类分数；再演示流式后验平滑的判决逻辑。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
B, Fbin, Tframe = 4, 40, 100     # 批 4, 40 梅尔频带, 100 帧（约 1 秒）

class DSConv(nn.Module):
    """深度可分离卷积：depthwise（每通道单独卷）+ pointwise（1x1 混通道）。"""
    def __init__(self, c_in, c_out):
        super().__init__()
        self.dw = nn.Conv2d(c_in, c_in, kernel_size=3, padding=1, groups=c_in)  # groups=c_in 是关键
        self.pw = nn.Conv2d(c_in, c_out, kernel_size=1)                          # 1x1 混通道
        self.bn = nn.BatchNorm2d(c_out)
    def forward(self, x):
        x = self.dw(x)           # 每个通道各卷各的, 参数极少
        x = self.pw(x)           # 通道间混合
        return F.relu(self.bn(x))

class TinyKWS(nn.Module):
    """small-footprint 唤醒词检测器：普通卷积打底 + 几层 DSConv + 池化 + 全连接。"""
    def __init__(self, n_mels=40, n_class=2):
        super().__init__()
        self.stem = nn.Sequential(
            nn.Conv2d(1, 16, kernel_size=3, stride=1, padding=1),
            nn.BatchNorm2d(16), nn.ReLU(),
        )
        self.body = nn.Sequential(DSConv(16, 32), DSConv(32, 32), DSConv(32, 32))
        self.head = nn.Linear(32, n_class)         # 池化后 32 维 → 2 类
    def forward(self, x):                          # x: [B, 1, F, T]
        x = self.stem(x)                           # -> [B, 16, F, T]
        x = self.body(x)                           # -> [B, 32, F, T]
        x = x.mean(dim=(2, 3))                     # 全局平均池化 -> [B, 32]
        return self.head(x)                        # -> [B, 2]  (非唤醒 / 唤醒)

model = TinyKWS()
mel = torch.randn(B, 1, Fbin, Tframe)              # 假梅尔谱 [B,1,40,100]
logits = model(mel)
print("mel   :", mel.shape)                        # torch.Size([4, 1, 40, 100])
print("logits:", logits.shape)                     # torch.Size([4, 2])

# 参数量：验证它确实"small-footprint"
n_params = sum(p.numel() for p in model.parameters())
print("params:", n_params)                         # 几万量级，几十 KB

# 训练用普通交叉熵；注意极端类不平衡时常给唤醒类更大权重
labels = torch.tensor([0, 1, 0, 0])                # 大多是负样本
loss = F.cross_entropy(logits, labels, weight=torch.tensor([1.0, 5.0]))  # 唤醒类加权
print("loss:", loss.item())
```

跑完看到：`[4,1,40,100]` 的梅尔谱经网络压成 `[4,2]` 的二分类分数；参数量几万（真实部署的 DS-CNN 就在这个量级，量化到 INT8 后几十 KB）。注意 `cross_entropy` 的 `weight` 给唤醒类加了权——这是对抗"负样本压倒性多"的常用手段。

下面是流式判决逻辑：模型逐帧吐后验，做滑动平均 + 持续超阈才唤醒。

```python
def streaming_decision(posteriors, tau=0.6, smooth_w=20, hold=10):
    """
    posteriors: [T] 每帧'是唤醒词'的后验概率
    tau: 判决阈值；smooth_w: 平滑窗帧数；hold: 需连续超阈的帧数
    """
    T = len(posteriors)
    smoothed = torch.zeros(T)
    run = 0                                   # 连续超阈计数
    for t in range(T):
        lo = max(0, t - smooth_w + 1)
        smoothed[t] = posteriors[lo:t+1].mean()   # 后验平滑：最近 smooth_w 帧均值
        if smoothed[t] > tau:
            run += 1
            if run >= hold:                   # 连续 hold 帧都超阈 → 判唤醒
                return True, t, smoothed
        else:
            run = 0                           # 掉下阈值就清零（必须"持续"高）
    return False, -1, smoothed

# 造一段后验：前期噪声尖峰 + 中段持续高（真唤醒）
post = torch.cat([
    torch.rand(30) * 0.5,                     # 背景：低且抖
    torch.tensor([0.95]),                     # 一个孤立尖峰（噪声误触）
    torch.rand(9) * 0.4,
    torch.ones(40) * 0.8 + torch.rand(40)*0.1 # 持续高：真唤醒事件
])
fired, at, sm = streaming_decision(post)
print("fired:", fired, "at frame:", at)       # 孤立尖峰不触发, 持续高段才触发
```

关键就在 `run` 这个计数器：**单个尖峰（哪怕 0.95）会被 `run` 清零挡掉，只有连续若干帧都超阈的持续事件才唤醒**——这正是第三节说的"用时间结构区分毛刺和事件"。调 `tau`/`hold` 就是在调 FAR/FRR 权衡。全部真实 API：`Conv2d(groups=)`、`cross_entropy(weight=)`，无发明函数。

## 六、这在工程里解决什么问题

| 约束 | KWS 的应对 |
|---|---|
| 毫瓦级功耗、几十 KB | 深度可分离卷积压参数；量化到 INT8；跑在低功耗小核 |
| 24 小时常开、不能重复算 | 带状态的流式卷积/RNN 复用历史，或降低判决频率 |
| 低延迟、严格因果 | 窗口只用历史帧；卷积 padding 砍右侧（和 ASR/3A 的因果化同理） |
| 极端类不平衡 | 损失给唤醒类加权；重点扩充多样负样本 |
| 远场/嘈杂误唤醒 | 远场/混响/加噪增广；专门挖发音相近的难负样本 |
| 误唤醒伤体验 | 先钉死 FA/hour 上限，再在约束下压漏唤醒 |

一线视角补充：
- **两级唤醒**是业界常规——第一级超小模型在 DSP 上粗筛（宁可多误报），触发后再唤醒主核上一个稍大的模型做二次确认，把误唤醒压下去。省电和准确两头兼顾。
- **个性化/自定义唤醒词**要少样本学习，常用说话人嵌入（下一篇声纹）或少样本注册来做。
- **指标口径要统一**：FA/hour 的"hour"是在什么负样本集上测的（安静？电视？），不说清就没法横向比。

## 七、埋一个钩子

到这里，KWS 回答的是"**说了什么词**"——内容。但紧接着常常要回答一个正交的问题：这句话"**是谁说的**"？自定义唤醒要认主人、门禁要认身份、会议记录要分清谁在发言。认人和认词用的是完全不同的建模——它要把一个人的声音压成一个可比对的"指纹向量"。下一篇进入**声纹识别**。

## 本篇小结

- **KWS 的本质**：不是识别整句，而是在**毫瓦功耗、几十 KB、严格因果、极端类不平衡**的约束下，把一个固定唤醒词从无尽背景声里可靠拎出来。设计全程被约束主导。
- **模型**：small-footprint 骨干，**深度可分离卷积**（depthwise + pointwise）把参数压一个数量级；纯卷积好量化、卷积+轻量 RNN 天然流式，按预算取舍。
- **流式判决**：别每帧重算整段（带状态复用历史）；别信单帧（**后验平滑** + 连续超阈才唤醒），利用唤醒词是"持续事件"而噪声是"瞬间尖峰"的时间结构。
- **FAR/FRR 权衡**：阈值 $\tau$ 让误唤醒和漏唤醒此消彼长；工业做法是钉死误唤醒上限（如 FA/24h ≤ 1），再在约束下最小化漏唤醒；数据上难在多样负样本与难负样本。
- **工程意义**：两级唤醒（小核粗筛 + 主核确认）兼顾省电与准确；自定义唤醒接声纹/少样本；指标口径（FA/hour 在什么负集上测）必须统一。
- **下一步**：从"认词"转到"认人"——把声音压成说话人指纹向量的声纹识别。
