# 语音深度学习模型精讲 · 写给转型算法工程师的实战笔记

> 前面几段旅程我们把地基打牢了：[《信号与系统》](../signals_and_systems/README.md) 讲清了采样、FFT、STFT、幅度与相位；深度学习基础把张量、反传、CNN/RNN/注意力拆成了零件；[《DL 3A 前端处理》](../3A-deeplearning/README.md) 用这些零件搭出了降噪、回声消除、生成式增强的主力模型。但那条线只覆盖了语音的**前端增强**一侧——把声音洗干净。这个系列补齐另一侧：**识别它说了什么（ASR）、把文字说出来（TTS）、一直醒着等一个词（语音唤醒）、认出是谁在说（声纹）**，最后用一整篇把这些模型**从训练到端侧部署**的工程链走通。

---

## 这个系列是什么

- **受众**：有音频/驱动背景、**已读完信号与系统 + 深度学习基础（最好也读过 3A 前端）**、正从驱动工程师转型语音算法工程师的人。
- **前置**（这些一律不再从头讲，直接当跳板引用）：
  - 来自 signals 系列：采样、FFT、STFT、语谱图、幅度与相位、梅尔谱。
  - 来自基础/3A 系列：张量 `[B,C,F,T]`/`[B,T,D]` 约定、nn.Module、反传、CNN 感受野、RNN/GRU 门控、注意力 Q/K/V、Conformer、SI-SNR/交叉熵、AdamW。
- **本系列讲什么**：把语音四大识别/合成任务里**真正被工业界和论文用起来的主力模型**各挑一个拆透——ASR 的 CTC/RNN-T、TTS 的 FastSpeech2+HiFi-GAN、唤醒的 small-footprint KWS、声纹的 ECAPA-TDNN，外加一篇自足重讲的掩码增强，最后收束到训练/微调/蒸馏/量化/部署。
- **不是什么**：不是论文综述、不是 SOTA 打榜清单、不做干涩数学证明、不罗列 API。
- **是什么**：一套"看得懂、能落地、能在面试里讲清楚"的模型级技术博客。每篇拆透一个模型/机制，直觉先行、代码兜底、工程视角贯穿。

## 写作风格与约束

全系列共同遵守的硬约束（与前几套系列一脉相承，详见 `_STYLE_GUIDE.md`）：

1. **直觉先行，数学兜底**：先给物理/工程画面，再上唯一核心公式，且逐项翻译成人话。绝不先甩推导。
2. **所有例子锚定语音**：识别、合成、唤醒、声纹、降噪、双讲。禁用猫狗分类/CIFAR/房价/NLP 英法翻译——注意力也用"语音帧互查"讲，不用词向量那套。
3. **比喻必须有解释力**：CTC 空白符=对齐用的占位符、时长预测器=给每个音素分配几帧画布、说话人嵌入=把一个人的声音压成一个指纹向量、量化=把连续旋钮换成有级档位。拒绝只换花哨说法、不推进理解的修辞。
4. **代码把公式变成可运行**：PyTorch 最小可跑实现，能 forward、shape 对得上、核心机制在。张量操作后**务必标注 shape**。一律内联在正文，**不生成独立脚本/PNG/WAV**，结构图用 ASCII/文字描述。
5. **讲"为什么需要"，落到工程**：实时因果红线（不看未来帧）、端侧算力/显存预算、流式推理的状态缓存、量化对定点/复数的影响、数据合成策略、指标与听感的背离。

## 目录（6 篇 + README）

**一 · 识别：音频 → 文字**
- `01_ASR端到端识别.md` — 不给逐帧标签，CTC 用"空白符"学会软对齐，RNN-T 把它改成能流式吐字；AED/Whisper 作对比

**二 · 合成：文字 → 音频**
- `02_TTS语音合成.md` — 两段式：声学模型（FastSpeech2 非自回归 + 时长预测器）先画梅尔，声码器（HiFi-GAN）再读成波形；VITS 端到端作对比

**三 · 常开：等一个词**
- `03_语音唤醒KWS.md` — 一个一直醒着、极省电、只认一个词的小网络；流式后验平滑、误唤醒/漏唤醒的阈值权衡

**四 · 认人：谁在说**
- `04_声纹识别.md` — 把变长语音压成一个固定维说话人嵌入；ECAPA-TDNN 的注意力统计池化 + AAM-Softmax 间隔损失，余弦打分与 EER

**五 · 洗干净：被噪声污染时**
- `05_语音增强自足版.md` — 不直接造声音，只给每个时频点学一个"保留多少"的掩码；小 CRN + 复数比值掩码，SI-SNR 训练（本篇自足，不依赖 3A 也能读）

**六 · 落地：从实验室到手机**
- `06_训练微调蒸馏量化部署.md` — 一个模型的全生命周期：数据增广 → 训练技巧 → 微调（全量/LoRA）→ 蒸馏 → 量化（PTQ/QAT）→ 部署（ONNX/TFLite、流式状态、因果红线、算力预算）

## 贯穿全系列的一条主线

6 篇不是 6 个孤岛，是一条连贯的河。每篇结尾的"埋一个钩子"都直接引出下一篇：

```
音频→文字(01 ASR)
   → 反过来 文字→音频(02 TTS)
   → 不要全部识别,只等一个词、还要常开省电(03 KWS)
   → 不认"说了什么",认"谁在说"(04 声纹)
   → 认人前先把噪声洗掉(05 增强)
   → 这五类模型怎么从训练一路落到端侧(06 工程)
```

一条更抽象的暗线贯穿始终——**不管识别、合成、认人还是降噪，核心难点都绕回同一处：音频是变长的时间序列，而你要的答案（一句话、一段波形、一个词、一个人、一张干净的谱）长度和它对不齐。** 怎么对齐、怎么池化成定长、怎么在"不能看未来帧"的实时红线下做这件事，是五篇反复出现的同一个问题。顺着读，你会发现任何一个复杂的语音模型，都不过是基础系列那些零件（卷积、门控、注意力、损失、池化）针对具体任务的重新组合。
