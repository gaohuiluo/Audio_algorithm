# 第 6 篇｜训练·微调·蒸馏·量化·部署：把实验室大模型塞进手机还能实时跑

> 一句话核心直觉：前五篇讲的识别、合成、唤醒、声纹、增强模型，训出来都是躺在大显存 GPU 上的浮点大家伙。要让它们跑在手机、耳机、音箱上，还隔着一整条工程链——**数据与增广**决定它见过什么、**训练技巧**决定它学得好不好、**微调**让它用少量数据适配新场景、**蒸馏**让大模型的本事搬进小模型、**量化**把浮点换成 INT8 省算力省内存、**部署**把它导成 ONNX/TFLite 还能流式实时跑。这一篇不讲新模型，讲的是把前五篇任何一个模型从实验室搬到端侧的完整 SOP。看懂这条链，你才算真的能"落地"语音算法。

## 一、先把教材那套扔一边

论文和教程讲模型，讲到"loss 收敛、指标达标"就结束了。可工业界的真相是：**训出一个指标好看的模型，只是工作的三分之一。** 剩下三分之二全在这一篇——怎么让它在手机上以 1/10 的内存、1/4 的算力、还不许看未来帧的前提下，达到接近实验室的效果。

这一篇是收官，把前五篇串起来：ASR 的 RNN-T、TTS 的 FastSpeech2+HiFi-GAN、KWS 的 DS-CNN、声纹的 ECAPA-TDNN、增强的 CRN——它们的落地都走同一条链。我们按这条链的顺序走：数据 → 训练 → 微调 → 蒸馏 → 量化 → 部署。每一环都给原理 + 一段能跑的 PyTorch + 一线踩坑。

> **关键认知**：端侧语音算法工程师的核心竞争力，不在于复现某篇论文，而在于**把一个模型沿这条链压到端侧预算之内、还能保住效果**。这条链上每一步都是在"精度"和"算力/内存/延迟"之间做交易，关键是知道哪一步该在哪里让步。

## 二、数据与增广：模型见过的世界有多大

模型的上限由数据决定。语音任务的数据工程有几个共性套路：

### 2.1 配对数据怎么来

- **ASR**：音频 + 转写文本。真实标注贵，常用半监督（用大模型打伪标签）扩充。
- **TTS**：高质量录音 + 文本 + 对齐时长（时长用强制对齐离线算，见第 1、2 篇）。
- **增强/AEC**：**在线合成**——干净语音 + 噪声按随机信噪比混（第 5 篇讲过），噪声库多样性决定泛化。
- **声纹**：大量说话人、每人多条、跨信道（手机/耳机/会议麦）。
- **KWS**：正样本（唤醒词）+ 海量多样负样本 + 难负样本（发音相近词）。

### 2.2 增广：用变换造出"没录过"的数据

增广是用廉价变换把一条数据变出很多条，逼模型学到不变性。语音最常用的几招，逐条说清治什么：

| 增广 | 做什么 | 治什么 |
|---|---|---|
| 加噪 | 混入不同噪声/信噪比 | 嘈杂环境鲁棒 |
| 混响 | 卷一个房间冲激响应 | 远场、回声环境 |
| 变速/变调 | 时间拉伸、基频平移 | 语速/音高多样性 |
| SpecAugment | 在语谱图上随机遮几条时间/频率带 | ASR 防过拟合（最有效的一招） |
| 音量扰动 | 随机增益 | 响度不敏感 |

> **关键认知**：**SpecAugment** 是 ASR 训练里性价比最高的增广——直接在梅尔谱上盖掉几条时间带和频率带，逼网络不要死记某几帧某几频，而是靠上下文推断。它几乎零成本、却能顶上大量真实数据的作用。

```python
import torch

def spec_augment(mel, n_time=2, n_freq=2, max_t=10, max_f=8):
    """SpecAugment：在梅尔谱上随机遮时间带和频率带。mel: [B, F, T]"""
    mel = mel.clone()
    B, Fb, T = mel.shape
    for b in range(B):
        for _ in range(n_time):               # 遮几条时间带
            t = torch.randint(0, max_t + 1, (1,)).item()
            t0 = torch.randint(0, max(1, T - t), (1,)).item()
            mel[b, :, t0:t0 + t] = 0
        for _ in range(n_freq):               # 遮几条频率带
            f = torch.randint(0, max_f + 1, (1,)).item()
            f0 = torch.randint(0, max(1, Fb - f), (1,)).item()
            mel[b, f0:f0 + f, :] = 0
    return mel

mel = torch.randn(2, 40, 100)
aug = spec_augment(mel)
print("mel:", mel.shape, "-> aug:", aug.shape)   # 形状不变，内容被遮了几块
```

## 三、训练技巧：显存不够、精度不稳怎么办

模型搭好、数据备齐，真正训起来会撞上三堵墙：显存不够、训练不稳、收敛慢。对应三组技巧。

### 3.1 混合精度：用 FP16/BF16 省显存提速

默认 FP32 每个数 4 字节。混合精度（AMP）用 FP16/BF16（2 字节）算前向反向，只在更新权重时用 FP32——显存减半、算力翻倍（现代 GPU 对半精度有专用单元）。坑是 FP16 动态范围小、梯度容易下溢成 0，要用**梯度缩放**（loss 乘个大数再反传、更新前除回来）兜住。

### 3.2 梯度累积：用时间换显存，撑大 batch

端侧模型 batch 要大才稳（尤其声纹的 AAM-Softmax、增强的 SI-SNR），但显存塞不下。梯度累积：跑 N 个小 batch、梯度**累加**不更新，第 N 次才更新一次——等效于 batch 大了 N 倍，代价是慢 N 倍。

### 3.3 学习率调度与课程

- **warmup + 衰减**：开头几步学习率从小爬到大（warmup，防一开始梯度乱把权重带飞），之后余弦/线性衰减。Transformer/Conformer 类几乎必须 warmup。
- **课程学习**（curriculum）：从易到难喂数据——增强先喂高信噪比再喂低信噪比、ASR 先短句后长句。让模型先学会简单的，再啃难的，比一上来就上最难的收敛稳。

```python
import torch
import torch.nn as nn

model = nn.Linear(64, 10)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
scaler = torch.amp.GradScaler("cuda", enabled=False)   # 有 GPU 时设 True
accum_steps = 4                                      # 梯度累积 4 步 = 等效 batch×4

for step in range(8):
    x = torch.randn(8, 64); target = torch.randint(0, 10, (8,))
    with torch.autocast(device_type="cpu", dtype=torch.bfloat16, enabled=False):
        loss = nn.functional.cross_entropy(model(x), target) / accum_steps  # 除以累积步数
    scaler.scale(loss).backward()                    # 梯度累加（不清零）
    if (step + 1) % accum_steps == 0:                # 攒够 N 步才更新一次
        scaler.step(opt); scaler.update(); opt.zero_grad()
        print(f"step {step}: updated, loss={loss.item()*accum_steps:.3f}")
```

> **关键认知**：这三招——混合精度省显存提速、梯度累积用时间换等效大 batch、warmup+课程稳住收敛——是任何语音模型训练的标配组合拳。它们不改模型，只改"怎么喂、怎么算、怎么更新"，却直接决定了你能不能在手上这块卡上把模型训出来。

## 四、微调：用少量数据适配新场景

你有一个在通用数据上训好的大模型（如 Whisper、一个通用降噪网），现在要让它在**你的特定场景**（某方言、某设备麦克风、某噪声环境）上更好。从头训太贵、数据也不够——微调（fine-tune）就是在预训练权重基础上，用少量目标数据接着训。

### 4.1 三档力度

- **全量微调**：所有参数都更新。效果上限最高，但要存一整份新权重、容易在小数据上过拟合、还会"灾难性遗忘"原本的通用能力。
- **只调部分层**：冻结骨干、只训最后几层/输出头。省、快、不易过拟合，适配能力有限。
- **参数高效微调（LoRA/适配器）**：冻结原权重，旁挂一个极小的可训练模块。这是当下主流。

### 4.2 LoRA：旁挂一个低秩小矩阵

LoRA 的想法：一个大权重矩阵 $W \in \mathbb{R}^{d\times d}$ 微调时的改变量 $\Delta W$ 其实"信息量不大"（低秩），那就不直接改 $W$，而是旁挂两个瘦长小矩阵 $A \in \mathbb{R}^{d\times r}$、$B \in \mathbb{R}^{r\times d}$（秩 $r \ll d$），用 $BA$ 来近似 $\Delta W$：

$$ W_{\text{eff}} = W + BA, \quad r \ll d $$

逐项翻译：原权重 $W$ 冻住不动，只训练 $A$、$B$ 这两个小矩阵；因为 $r$ 很小（比如 8），要训的参数量从 $d^2$ 降到 $2dr$，少几十上百倍。推理时把 $BA$ 加回 $W$，不增加任何推理成本。

> **关键认知**：LoRA 让你**用几 MB 的增量权重，适配一个几百 MB 的模型**。一个底座、每个场景一份小 LoRA，部署时按需加载——这是多场景语音产品的标准玩法。而且冻住底座天然缓解了灾难性遗忘。

```python
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    """给一个冻结的 Linear 旁挂低秩 A、B。"""
    def __init__(self, base: nn.Linear, r=8, alpha=16):
        super().__init__()
        self.base = base
        for p in self.base.parameters():       # 冻结原权重
            p.requires_grad = False
        d_in, d_out = base.in_features, base.out_features
        self.A = nn.Parameter(torch.randn(d_in, r) * 0.01)   # [d_in, r]
        self.B = nn.Parameter(torch.zeros(r, d_out))         # [r, d_out] 初始为0 → 开局不扰动
        self.scale = alpha / r
    def forward(self, x):                      # x: [B, d_in]
        return self.base(x) + (x @ self.A @ self.B) * self.scale   # 原输出 + 低秩增量

base = nn.Linear(256, 256)
lora = LoRALinear(base, r=8)
x = torch.randn(4, 256)
y = lora(x)
trainable = sum(p.numel() for p in lora.parameters() if p.requires_grad)
total = sum(p.numel() for p in lora.parameters())
print("out:", y.shape, "| trainable:", trainable, "/", total)   # 可训参数只占百分之几
```

B 初始化为 0 是关键——开局 $BA=0$，微调从"不改变原模型"平滑起步，训练稳。可训参数只占总量的百分之几。

## 五、蒸馏：把大模型的本事搬进小模型

微调是适配，蒸馏是**压缩**——用一个训好的大模型（teacher）教一个小模型（student），让小模型以 1/10 的体量达到接近大模型的效果。

### 5.1 为什么教"软标签"比教"硬标签"强

直接拿标注训小模型，它只学到"正确答案是第 3 类"（硬标签 one-hot）。但大模型输出的是一个**概率分布**（软标签）——比如"80% 是'是'、15% 像'四'、5% 是别的"。这个分布里藏着大模型学到的**类间关系**（"是"和"四"发音近，所以第二高）。让小模型去模仿这个分布，等于把大模型的"经验直觉"也传了过去。

蒸馏损失 = 蒸馏项（学软标签）+ 普通项（学硬标签）：

$$ L = \alpha\, T^2\, \mathrm{KL}\big(\text{softmax}(z_s/T)\,\|\,\text{softmax}(z_t/T)\big) + (1-\alpha)\, \mathrm{CE}(z_s, y) $$

逐项翻译：$z_s, z_t$ 是学生、老师的 logits；温度 $T$ 把分布"软化"（T 越大分布越平、越能暴露类间关系），注意 KL 前乘 $T^2$ 是为了配平梯度尺度；$\alpha$ 平衡"学老师"和"学真答案"。

### 5.2 语音里的三种蒸馏

- **logit 蒸馏**：学老师的输出分布（上面的公式），通用。
- **特征蒸馏**：让学生中间层特征去逼近老师中间层——语音大模型（如 wav2vec/Whisper 编码器）常这么蒸，因为中间表示比最终输出信息更丰富。
- **序列级蒸馏**：ASR 这类序列输出，用老师解码出的伪转写当学生的训练目标，比逐帧对齐更稳。

```python
import torch
import torch.nn.functional as F

def distill_loss(student_logits, teacher_logits, labels, T=4.0, alpha=0.7):
    # 蒸馏项：软化后的 KL（学老师的"软答案"）
    s = F.log_softmax(student_logits / T, dim=-1)
    t = F.softmax(teacher_logits / T, dim=-1)
    kl = F.kl_div(s, t, reduction="batchmean") * (T * T)
    # 普通项：对真实硬标签的交叉熵
    ce = F.cross_entropy(student_logits, labels)
    return alpha * kl + (1 - alpha) * ce

sl = torch.randn(4, 10, requires_grad=True)   # 学生 logits
tl = torch.randn(4, 10)                        # 老师 logits（teacher 冻结、no_grad）
lb = torch.randint(0, 10, (4,))
print("distill loss:", distill_loss(sl, tl, lb).item())
```

> **关键认知**：微调改的是"模型会什么"，蒸馏改的是"模型多大"。端侧常把两者连用——先微调一个大 teacher 到目标场景，再蒸馏成能上端侧的 small student。KWS 的两级唤醒、端侧 ASR，背后几乎都有蒸馏。

## 六、量化：把浮点换成整数，省 4 倍内存和算力

模型训好、压小了，权重还是 FP32。端侧要**量化**成 INT8——每个数从 4 字节变 1 字节，内存降 4 倍，整数运算还比浮点快、省电。

### 6.1 原理：把连续旋钮换成有级档位

量化就是把一段连续的浮点范围 $[\min, \max]$ 映射到 256 个整数档位（INT8）：

$$ q = \mathrm{round}(x / s) + z, \qquad x \approx s\,(q - z) $$

逐项翻译：$s$ 是缩放系数（scale，一档代表多大的浮点跨度）、$z$ 是零点（zero-point，浮点 0 对应哪个整数档）。把浮点 $x$ 除以 $s$ 四舍五入到最近档位、推理时再乘回去近似还原。误差来自那个 round——这就是"把连续旋钮换成有级档位"的字面意思，档位不够细就有量化噪声。

### 6.2 两条路：PTQ vs QAT

- **训练后量化（PTQ）**：训练完直接量化，用一小批**校准数据**跑一遍统计每层激活的 $[\min,\max]$ 定出 $s, z$。快、不用重训，但低比特下精度可能掉。
- **量化感知训练（QAT）**：训练时就**模拟量化**（前向插入"假量化"节点让网络提前适应 round 误差，反向用直通估计让梯度照常流）。慢、要重训，但精度保得住。

选择原则：先试 PTQ，精度够就收工；掉太多再上 QAT。

```python
import torch
import torch.nn as nn

# PTQ 最简形态：动态量化（权重 INT8，激活运行时量化），适合 Linear/LSTM 多的模型
model = nn.Sequential(nn.Linear(256, 256), nn.ReLU(), nn.Linear(256, 128))
model.eval()
qmodel = torch.quantization.quantize_dynamic(
    model, {nn.Linear}, dtype=torch.qint8        # 只量化 Linear 层的权重
)
x = torch.randn(1, 256)
print("fp32 out:", model(x).shape, "| int8 out:", qmodel(x).shape)

fp32_size = sum(p.numel() * 4 for p in model.parameters())        # FP32: 4 字节/参数
print(f"FP32 权重约 {fp32_size/1024:.1f} KB，INT8 权重约 {fp32_size/4/1024:.1f} KB（约 1/4）")
```

### 6.3 语音量化的特有坑

> **关键认知**：量化对语音模型有几个比通用模型更毒的坑——(1) **RNN/GRU 的状态在定点下误差会逐帧累积**（第 3、5 篇的流式模型都中招），QAT 几乎必须；(2) **复数运算**（第 5 篇 CRM 的实虚两路相乘）在定点下易溢出，要单独留 headroom；(3) **声码器**（第 2 篇 HiFi-GAN）对量化极敏感，一点量化噪声就在波形上听得出来，往往只能量化到 INT8 的保守配置甚至保留部分浮点。量化不是无脑一键，哪层能量化、量化到几比特，得按模块的敏感度逐一试。

## 七、部署：导出、流式、因果、算力预算

最后一公里：把量化好的模型从 PyTorch 搬到端侧运行时。

### 7.1 导出格式

- **ONNX**：跨框架中间格式，再转各家推理引擎（手机 NPU、PC 的 ORT）。
- **TFLite**：移动端（尤其安卓）主流，对 INT8、硬件加速支持好。
- **厂商 SDK**：高通 SNPE、联发科 NeuroPilot 等，吃厂商 NPU 的算力。

导出要防"训练算子端侧不支持"——复数运算、自定义 pooling、动态 shape 常是雷区，导不过去就得改写成端侧支持的等价算子。

### 7.2 流式与状态缓存

实时语音模型不能"等一整句再算"，要**逐帧/逐块推理**。关键是**状态缓存**：

- **RNN/GRU**：把隐状态存下来，下一帧带着上一帧的状态进来（第 3、5 篇讲过）。
- **卷积**：缓存窗口左侧的历史帧（ring buffer），避免重复计算（第 1 篇下采样、第 5 篇因果卷积同理）。
- **注意力/Conformer**：缓存历史 K/V 和一个有限的注意力窗口（不能缓存无限历史，端侧扛不住）。

### 7.3 因果红线

这条贯穿全系列：**端侧实时不能看未来帧**。所有卷积要因果化（padding 砍右侧）、注意力只看历史、下采样对齐要对（第 1 篇那个 input_lengths 的 off-by 坑在流式下更致命）。训练时如果用了双向结构（如第 1 篇的 BiGRU、第 5 篇看未来帧的卷积），上流式前必须改成单向/因果，否则线上行为和离线评测对不上。

### 7.4 算力预算怎么算

端侧选型先算三笔账：

| 预算 | 怎么估 | 典型红线 |
|---|---|---|
| 内存 | 参数量 × 字节数（INT8 为 1） | KWS 几十 KB、端侧 ASR/增强几 MB |
| 算力 | 每帧乘加次数 × 帧率（如 100 帧/秒） | 必须 < 实时（算一帧 < 10ms） |
| 功耗 | 常开模型（KWS）跑在低功耗核，毫瓦级 | 决定续航 |

> **关键认知**：部署阶段的全部判断，都归到一个问题——**算一帧的时间，必须小于一帧的时长**（16kHz、hop 160 的话一帧 10ms）。算不过来就不是实时。沿这条链一路做的数据/训练/蒸馏/量化，最终都是为了把"算一帧"压进这 10ms 里，还不丢太多精度。

## 八、这在工程里解决什么问题：一条链的全景

把前五篇任一模型落到端侧，就是走一遍这条链，每步在做一笔精度/成本的交易：

| 环节 | 解决什么 | 代价/风险 |
|---|---|---|
| 数据+增广 | 决定模型见过多大的世界、鲁棒性 | 合成/增广过度会偏离真实分布 |
| 训练技巧 | 在有限显存上把模型训出来、训稳 | 混合精度要防下溢、累积换时间 |
| 微调(LoRA) | 少量数据适配新场景，一底座多场景 | 全量微调会遗忘、过拟合 |
| 蒸馏 | 把大模型本事搬进端侧小模型 | 蒸馏上限受 teacher 和结构限制 |
| 量化 | 内存降 4 倍、整数运算省电提速 | RNN 状态累积、复数溢出、声码器敏感 |
| 部署 | 导出 + 流式 + 因果 + 卡进算力预算 | 算子不支持、未来帧泄漏、超实时 |

## 九、全系列收尾

六篇走下来，你手里应该有两张地图了。

一张是**模型地图**：音频→文字（ASR 的对齐）、文字→音频（TTS 的两段式）、常开认词（KWS 的小模型）、认人（声纹的指纹向量）、洗噪（增强的掩码）。你会发现它们反复用同一批零件——卷积抓局部、GRU/注意力建时间、池化压定长、各种损失塑造目标——只是针对任务重新组合。

另一张是**落地地图**：这一篇的链。任何一个模型从论文到手机，都要走数据→训练→微调→蒸馏→量化→部署，每步在精度和算力之间做交易，最终目标是把"算一帧"压进实时红线。

> 把这两张地图叠起来，你就有了语音算法工程师真正吃饭的本事：既懂模型为什么这么设计，也懂它凭什么能跑在端侧。这正是从"音频驱动"转"语音算法"要补齐的那块拼图。

## 本篇小结

- **数据与增广**：配对数据的来路各任务不同（增强靠在线混噪、TTS 靠对齐时长）；SpecAugment 是 ASR 性价比最高的增广。
- **训练技巧**：混合精度省显存提速（防梯度下溢）、梯度累积用时间换等效大 batch、warmup+课程学习稳住收敛——不改模型的标配组合拳。
- **微调**：全量/部分层/参数高效三档；**LoRA** 冻底座旁挂低秩小矩阵，几 MB 增量适配几百 MB 模型、一底座多场景、天然抗遗忘，B 初始化为 0 平滑起步。
- **蒸馏**：教"软标签"比"硬标签"多传了类间关系；logit/特征/序列级三种，端侧常"先微调大 teacher 再蒸成小 student"。
- **量化**：把连续浮点映射到 INT8 档位（scale+zero-point），内存降 4 倍；PTQ 快但可能掉点、QAT 重训但保精度；RNN 状态累积、复数溢出、声码器敏感是语音特有坑。
- **部署**：ONNX/TFLite 导出防算子不支持；流式靠状态缓存（RNN 隐状态/卷积 ring buffer/注意力有限 K-V 窗口）；因果红线不看未来帧；算力预算归结为"算一帧 < 一帧时长"。
- **收尾**：模型地图（同一批零件的任务重组）+ 落地地图（这条链的精度/成本交易），叠起来就是语音算法工程师的核心本事。
