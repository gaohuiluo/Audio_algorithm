## 一、收官之前，先把地图铺开

这是本系列的最后一篇。走到这里，你手上其实已经攒齐了做一个语音系统所需的全部零件。我们先把它们摆在一张桌子上，看清每块积木是干什么的：

| 篇章 | 积木 | 在 Pipeline 里干的活 |
|------|------|---------------------|
| 第 1~3 篇 | 采样、量化、离散信号 | 把声音变成一串能计算的数字 |
| 第 4~5 篇 | LTI 系统、冲激响应、卷积 | 理解"滤波""混响"到底是什么运算 |
| 第 6~8 篇 | 傅里叶变换、频谱 | 把时域波形拆成频率成分 |
| 第 9 篇 | 短时傅里叶变换、加窗、分帧 | 处理"语音是变化的"这一现实 |
| 第 16 篇 | 源-滤波器模型 | 把语音理解成"激励 × 声道" |
| 第 17 篇 | 倒谱、MFCC | 提取识别用的紧凑特征 |

一条真实的语音处理流水线，几乎永远是这套骨架：

```
原始波形
   │
   ▼  ① 分帧 + 加窗        (第 9 篇: 语音只在短时内平稳)
   ▼  ② 每帧 FFT → 频谱    (第 6~8 篇: 进入频域)
   ▼  ③ 在频域做处理        (判决 / 增强 / 提特征)
   ▼  ④ 逆变换 (若需还原音频) 或 输出特征/判决
   ▼
结果 (干净语音 / VAD 标签 / MFCC)
```

第 ③ 步填什么，决定了你在做什么任务。今天我们填两样最经典的：**语音活动检测 (VAD)** 和 **谱减法降噪 (Spectral Subtraction)**。

## 二、任务一：VAD——判断"这一帧有没有人在说话"

### 为什么需要它

几乎每个语音系统的第一道工序都是 VAD。语音识别不想把静音和喘气声送进模型浪费算力；录音软件想自动裁掉开头结尾的空白；实时通话想在你不说话时省带宽。**VAD 就是给每一帧贴一个标签：语音 / 非语音。**

### 直觉先行

怎么判断一帧里有没有人说话？两个朴素信号，你日常就在用：

1. **能量**：说话时声波振幅大、能量高；静音时能量低。这是最直接的线索。
2. **频谱形状**：但光看能量会被"低频轰隆的空调噪声"骗到——它能量也不低。人说话的能量更多铺在中高频（还记得第 16 篇的共振峰吗，元音的能量集中在几百到几千赫兹）。所以再看一个量：**过零率 (Zero-Crossing Rate)**——波形每秒穿过零点的次数。清音（s、f 这类摩擦音）和噪声过零率高，浊音过零率低、能量高。能量 + 过零率两者配合，比单看能量稳得多。

### 代码实战

```python
import numpy as np
import matplotlib.pyplot as plt

fs = 16000

# ---------- 造一段测试信号: 静音 - 语音 - 静音 - 语音，全程叠加噪声 ----------
def make_speechlike(dur, fs, f0=140):
    N = int(fs*dur); exc = np.zeros(N); exc[::int(fs/f0)] = 1.0
    from scipy.signal import lfilter
    a = [1.0]
    for f, bw in [(700,80),(1200,90),(2600,120)]:
        r=np.exp(-np.pi*bw/fs); th=2*np.pi*f/fs
        a=np.convolve(a,[1,-2*r*np.cos(th),r*r])
    s = lfilter([1.0], a, exc); return s/np.max(np.abs(s))

rng = np.random.default_rng(0)
sil = lambda d: np.zeros(int(fs*d))
clean = np.concatenate([sil(0.3), make_speechlike(0.5,fs),
                        sil(0.4), make_speechlike(0.6,fs), sil(0.3)])
noise = 0.05*rng.standard_normal(len(clean))
signal = clean + noise

# ---------- 分帧 ----------
def frame_signal(x, flen, hop):
    n = 1 + (len(x)-flen)//hop
    return np.stack([x[i*hop:i*hop+flen] for i in range(n)]), hop

flen, hop = int(fs*0.025), int(fs*0.010)
frames, hop = frame_signal(signal, flen, hop)
win = np.hamming(flen)

# ---------- 逐帧算两个特征 ----------
energy = np.array([np.sum((f*win)**2) for f in frames])
zcr    = np.array([np.mean(np.abs(np.diff(np.sign(f)))>0) for f in frames])
energy_db = 10*np.log10(energy + 1e-10)

# ---------- 判决: 用前若干帧(假定为噪声)自适应定阈值 ----------
noise_floor = np.mean(energy_db[:20])
thr = noise_floor + 8          # 高出本底 8 dB 判为语音
vad = energy_db > thr

# ---------- 画结果 ----------
t = np.arange(len(signal))/fs
tf = np.arange(len(frames))*hop/fs
fig, ax = plt.subplots(3,1, figsize=(11,7), sharex=True)
ax[0].plot(t, signal); ax[0].set_title('Noisy waveform'); ax[0].set_ylabel('Amp')
ax[1].plot(tf, energy_db); ax[1].axhline(thr, color='r', ls='--', label='threshold')
ax[1].set_title('Frame energy (dB)'); ax[1].legend(); ax[1].set_ylabel('dB')
ax[2].step(tf, vad.astype(int), where='mid'); ax[2].set_title('VAD decision (1=speech)')
ax[2].set_ylabel('speech?'); ax[2].set_xlabel('Time (s)'); ax[2].set_ylim(-0.2,1.2)
plt.tight_layout(); plt.show()

print(f"总帧数 {len(vad)}, 判为语音 {vad.sum()} 帧 ({100*vad.mean():.0f}%)")
```

跑完，第三张图的方波会准确地在两段语音处跳到 1、在静音处落回 0。**注意那个阈值不是硬编码的**——我们假设开头 20 帧是噪声、据此自适应地把阈值定在本底之上。这是工程里非常常见的手法：环境噪声千变万化，能自适应的系统才活得下去。

![三联图：带噪波形、逐帧能量(dB)及自适应阈值、VAD 判决，能量越过阈值的两段被判为语音](fig_18_1_1.png)

真实产品级 VAD（如 WebRTC VAD、Silero VAD）会用更多特征、甚至神经网络，但**内核逻辑没变：分帧 → 逐帧算特征 → 判决**。你现在写的这个，就是它们的骨架。

## 三、任务二：谱减法降噪——在频域里"擦掉"噪声

### 为什么需要它，直觉是什么

设想一段带着稳定空调声的录音。空调声是**持续、稳定**的，它在频谱上的样子几乎不随时间变；而人声是**起伏变化**的。

于是有了一个朴素到近乎天真、却真的管用的想法：

> 先在没人说话的时候（VAD 正好帮我们找到这种片段！），估计出**噪声的频谱长什么样**；然后在每一帧的频谱上，把这份噪声频谱**减掉**。剩下的，就主要是人声了。

这就是**谱减法 (Spectral Subtraction)**。它把第 5 篇"时域卷积 = 频域相乘"的思想又推进一步：**在频域里，加性噪声就是频谱上的加项，那降噪自然就是减法。** 时域里难缠的混叠问题，换到频域，变成了一道减法题。

### 关键细节：为什么用 STFT，为什么要保留相位

- 噪声频谱只在**局部时间**稳定，所以必须**分帧**做——这正是第 9 篇短时傅里叶变换 (STFT) 的用武之地。
- FFT 出来的是复数（幅度 + 相位）。我们只在**幅度谱**上做减法，**相位原封不动地留用**。为什么？因为人耳对相位远不如对幅度敏感，而准确重建相位极难——保留带噪相位是性价比最高的工程折中。这是"完美"与"够用且能实时跑"之间的经典取舍。

### 代码实战

```python
# 接续上面的 signal, fs, flen, hop, win

def stft(x, flen, hop, win):
    frames,_ = frame_signal(x, flen, hop)
    return np.fft.rfft(frames*win, axis=1)        # (帧, 频点) 复数

def istft(S, flen, hop, win, length):
    frames = np.fft.irfft(S, n=flen, axis=1)*win  # 逆变换 + 合成窗
    out = np.zeros(length); wsum = np.zeros(length)
    for i, f in enumerate(frames):
        s = i*hop
        out[s:s+flen]  += f
        wsum[s:s+flen] += win**2                  # 重叠相加(OLA)归一化
    return out/np.maximum(wsum, 1e-8)

# ---------- 1. 用前 20 帧(静音段)估计噪声幅度谱 ----------
S = stft(signal, flen, hop, win)
mag, phase = np.abs(S), np.angle(S)
noise_mag = np.mean(mag[:20], axis=0)             # 噪声幅度谱模板

# ---------- 2. 逐帧减去噪声谱(带下限保护,避免出现负值/音乐噪声) ----------
alpha = 1.5                                        # 过减因子
floor = 0.05                                       # 谱下限(保留一点残余,防"音乐噪声")
clean_mag = mag - alpha*noise_mag
clean_mag = np.maximum(clean_mag, floor*mag)       # 不低于原幅度的 5%

# ---------- 3. 幅度用降噪结果, 相位沿用原始, 逆变换回时域 ----------
S_clean = clean_mag * np.exp(1j*phase)
enhanced = istft(S_clean, flen, hop, win, len(signal))

# ---------- 对比: 输入 SNR vs 输出 SNR (用干净信号做参考) ----------
def snr(ref, x):
    m = min(len(ref), len(x)); ref, x = ref[:m], x[:m]
    return 10*np.log10(np.sum(ref**2)/(np.sum((x-ref)**2)+1e-10))
print(f"降噪前 SNR: {snr(clean, signal):.1f} dB")
print(f"降噪后 SNR: {snr(clean, enhanced):.1f} dB")

fig, ax = plt.subplots(2,1, figsize=(11,5), sharex=True)
ax[0].plot(np.arange(len(signal))/fs, signal); ax[0].set_title('Before: noisy')
ax[1].plot(np.arange(len(enhanced))/fs, enhanced); ax[1].set_title('After: spectral subtraction')
ax[1].set_xlabel('Time (s)'); plt.tight_layout(); plt.show()
```

跑完你会看到打印出的 SNR 提高了几个 dB，波形图里静音段的噪声地毯明显被压平了。

![谱减法降噪前后波形对比：上为带噪信号，下为处理后信号，静音段的噪声底显著被压平](fig_18_2_1.png)

这里藏着两个真实工程里绕不开的旋钮，值得你记住：

- **过减因子 `alpha`**：减得越狠，噪声压得越干净，但也越容易把人声一起削掉、产生失真。
- **谱下限 `floor`**：如果无脑减到 0，残留噪声会变成一种忽有忽无、叮叮当当的**"音乐噪声" (musical noise)**——这是谱减法臭名昭著的副作用。留一个下限，用"轻微稳定的残余噪声"换掉"讨厌的音乐噪声"，是标准做法。

**没有免费的午餐**——降噪永远是"去噪"和"保真"之间的权衡。理解了这一点，你才算真懂了这个算法，而不只是会调库。

## 四、把两件事串成一条完整 Pipeline

现在把 VAD 和谱减法接起来，就是一条有模有样的语音前端：

```
录音波形
   │
   ▼  分帧 + 加窗
   ▼  ┌── VAD: 找出静音段 ──┐
   ▼  │                      ▼
   ▼  │             用静音段估计噪声谱
   ▼  │                      │
   ▼  └──────────────────────┤
   ▼                          ▼
   ▼             谱减法降噪 (STFT → 减 → ISTFT)
   ▼                          │
   ▼               （可选）对语音段提 MFCC
   ▼
干净语音 + 帧级语音标签 (+ 特征)
```

注意这里的巧妙咬合：**VAD 找出的静音段，正好喂给谱减法当噪声模板**——两块积木不是并排放着，而是互相供料。这种"上一步的副产品正好是下一步的输入"的结构，是真实系统的常态。你在第 16、17 篇也见过同样的接力：源-滤波器的解耦思想，被倒谱接手做成了 MFCC。

## 五、格局：这套框架如何一路长成"深度学习语音算法"

你可能会想：都 2026 年了，端到端神经网络当道，我手写这些经典算法还有意义吗？

有，而且是决定性的。因为**现代深度学习语音系统，并没有推翻这套框架，而是站在它肩膀上**：

- **输入还是它**：绝大多数语音大模型（ASR、TTS、声纹、语音增强）的输入，仍是**梅尔频谱**或 **MFCC**——正是第 17 篇那条流水线的产物。你今天写的分帧、加窗、FFT、梅尔滤波，就是喂给 Transformer 的那份"食材"的做法。

- **任务还是它**：神经网络做的 VAD、降噪、分离，解决的是**和今天一模一样的问题**，只是把"手工设阈值、手工减噪声谱"换成了"让模型从数据里学出最优的判决和映射"。你理解了谱减法在权衡什么（去噪 vs 保真、音乐噪声），才能看懂一个神经降噪模型的 loss 为什么那样设计、它的失真从哪来。

- **世界观还是它**：源-滤波器的解耦思想活在现代神经声码器里（如 WaveNet、HiFi-GAN 仍隐含"激励 + 声道"结构）；卷积（第 5 篇）就是 CNN 里的卷积层；频域处理是几乎所有音频模型的第一层。

**深度学习不是让这些知识过时，而是让它们变成你读懂论文、调通模型、定位问题的底层视力。** 一个只会调 `model.fit()` 的人，和一个知道"输入的梅尔谱每一维意味着什么、降噪失真为什么出现、VAD 漏检该从哪查"的人，做出来的东西天差地别。你想转行做语音算法，缺的从来不是框架 API，而是今天这套贯穿信号本质的直觉——现在，你有了。

## 本篇小结

- **Pipeline 骨架**：分帧加窗 → FFT 进频域 → 频域处理（判决/增强/提特征）→ 逆变换或输出。几乎所有语音系统都是这套结构。
- **VAD**：逐帧看能量 + 过零率，自适应定阈值，给每帧贴"语音/非语音"标签；是语音系统的第一道工序。
- **谱减法降噪**：用静音段估噪声谱，在幅度谱上减掉、保留原相位；核心权衡是去噪 vs 保真，过减会产生"音乐噪声"。
- **积木咬合**：VAD 找的静音段正好当谱减法的噪声模板——真实系统里各模块互相供料。
- **通向深度学习**：现代语音大模型的输入（梅尔谱/MFCC）、任务（VAD/降噪/合成）、世界观（源-滤波器、卷积、频域）全都长在这套框架上。经典信号处理是读懂、调通、诊断现代模型的底层视力。
- **全系列终点**：把公式翻译回物理现实、再翻译成可跑的代码——这就是从"会算"到"真懂"，也是你转行语音算法真正需要的地基。
