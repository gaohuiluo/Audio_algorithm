# 信号与系统 · 写给音频工程师的重学笔记

> 考研背下来的《信号与系统》，公式会算、心里没底。这个系列把每个概念**重新落回声音本身**——先讲清"工程里到底在解决什么问题"，再上极简公式，最后用 Python 把它画成能看的波形。目标是真正"懂"，为转做语音信号处理算法打底。

---

## 这个系列是什么

- **受众**：有音频/驱动背景、想把信号与系统从"会算"变成"真懂"的工程师。
- **不是什么**：不是教材、不是公式手册、不做干涩的定理证明。
- **是什么**：一套"看得懂、能听明白"的技术博客，每篇一个核心概念，直觉先行、代码兜底。

---

## 写作风格与约束

这些是全系列共同遵守的硬约束，续写或改写任何一篇都应对齐：

### 1. 直觉先行，数学兜底
每个概念**先给物理画面，再上公式**。公式只保留最核心的那一个，出现时必须逐项翻译成人话。绝不先甩一堆推导。
> 例：卷积先带你"进山洞拍手听回响"，等直觉建立了，$y[n]=\sum_k x[k]h[n-k]$ 就变得顺眼。

### 2. 所有例子锚定音频/语音场景
一律用声音、语音、音频处理举例。**禁用电路、无线电、通信这类传统教材例子**。读者每天打交道的是 `float32` 数组、PCM 数据、混响插件——例子要落在这些东西上。

### 3. 比喻必须有解释力，拒绝装饰性换名
只保留能**揭示机制**的比喻（拍手回声叠加=卷积、X 光曝光=冲激响应探测系统）。坚决去掉只换个花哨说法、却不推进理解的修辞（如无解释力的"声学指纹""声音画像"）——那只增加认知负荷。直接描述事物本身。

### 4. 代码把公式变成可视化
用 Python（NumPy + Matplotlib）把概念跑出来，画成波形/频谱/收敛曲线，让读者"看到"而不是"想象"。代码要能直接运行、注释讲清每步在干嘛。

### 5. 讲"为什么需要"，落到工程
重点是"工程中遇到什么问题、为什么要这个工具"，而不是定理本身。凡有条件，补一段一线工程视角（如驱动层的 Ring Buffer 时间对齐坑）。

## 每篇的固定骨架

```
# 第 N 篇｜主题：一句话副标题
> 一句话核心直觉：……            ← 开篇 blockquote，全篇的锚

## 一、先把教材那句定义扔一边      ← 破除抽象定义，换生活场景切入
## 二～N、物理直觉 + 极简公式       ← 分节推进，关键处用 > 引用块标"关键认知"
## 代码实战                        ← Python 可视化，看到概念长什么样
## 埋一个钩子                      ← 抛出下一篇要解决的问题，形成连贯脉络
## 本篇小结                        ← bullet 收尾：概念 / 工程意义 / 下一步
```

排版习惯：核心公式用 `$$...$$`；"关键认知"用 `>` 引用块高亮；工程对照常用表格；代码块给完整可运行片段。

## 配套代码

大部分篇目内含可运行的 Python 片段。第 19 篇附独立脚本与产物：

| 文件 | 内容 |
|---|---|
| `aec_lms_demo.py` | NLMS 回声消除主 demo：三张收敛图 + 三段对比 wav |
| `aec_doubletalk_demo.py` | 双讲对比：有/无 DTD 时权重是否被打飞 |
| `aec_*.png` / `aec_*.wav` | 收敛可视化与"污染前/后/消除后"音频 |

运行环境：Python 3 + NumPy + Matplotlib。示例：

```bash
python aec_lms_demo.py
```
