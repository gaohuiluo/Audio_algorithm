# 第 13 篇｜FFT 与 STFT：让声音"显形"为语谱图

> 一句话核心直觉：这一篇有两位主角。**FFT** 是算 DFT 的一台高速引擎——答案和第 12 篇的 DFT 分毫不差，只是把重复的活儿全省了，快到离谱；**STFT** 则是把声音切成一小片一小片、逐片做 FFT 再横着拼起来，得到那张能"看见"声音随时间流动的彩色图——**语谱图 (Spectrogram)**。我们不满足于一个比喻，要把这两件事从**物理直觉、数学骨架、工程落地**三个角度都吃透。

---

## 一、承上：上一篇结尾卡住的两道坎

第 12 篇我们从连续傅里叶变换一路妥协到电脑真能算的 DFT：

$$X[k] = \sum_{n=0}^{N-1} x[n]\,e^{-j\frac{2\pi}{N}kn}, \qquad k=0,1,\dots,N-1$$

$N$ 个数进、$N$ 个数出，有限、离散、可计算。但那一篇的结尾，我们撞上了两道坎：

1. **DFT 按定义直接算，太慢。** 每个 $X[k]$ 要把 $N$ 个 $x[n]$ 各乘一个复数再累加，$N$ 个 bin 就是约 $N^2$ 次复数乘加。$N=8192$ 时是六千多万次——想实时分析音频，扛不住。
2. **一整段声音只做一次 DFT，会把"何时发生"糊掉。** 第 7 篇我们拆过棱镜这个比喻：对整段信号做傅里叶变换，会把**时间信息彻底抹平**，它只回答"这段里有哪些频率、各多强"，绝不回答"某个频率什么时候出现"。可语音每时每刻都在变——一句"你好"，声带频率在滑动，"你"和"好"的共振峰完全不同，拍成一张频谱就是一团糨糊。

这一篇的两位主角，正好一人解一道坎：**FFT 解决"慢"，STFT 解决"糊"**。它们联手的产物，就是你在几乎每个语音工具里都见过的那张彩色语谱图。

先讲 FFT（第二～五节），再讲 STFT（第六节起）。

---

## 二、FFT：同一个答案，只是不再重复做功

先把最容易误解的一件事焊死，免得你把它记成两种东西：

> **关键认知**：**FFT（快速傅里叶变换）算出来的结果，和 DFT 完全一样——一个数都不差。** FFT 不是另一种变换，不是近似，不是"精度换速度"。它就是 DFT，只不过换了一套聪明的运算顺序，把计算量从 $O(N^2)$ 砍到 $O(N\log_2 N)$。凡是 DFT 能给你的（频率 bin、幅度、相位、泄漏、$\Delta f=f_s/N$ 那套换算），FFT 原样给你，只是算得飞快。

所以这一节不讲"新变换"，只讲一个问题：**同样的 $X[k]$，怎么算能少做几千倍的功？**

### 2.1 先看清"慢"到底慢在哪：$N^2$ 次里藏着大量重复

回到定义。为了少写点符号，把那个旋转因子（第 3 篇的复指数、第 12 篇的探针）单独起个名：

$$W_N = e^{-j\frac{2\pi}{N}}$$

它是一个单位圆上的复数，模长恒为 1，作用是"旋转一个固定角度"。于是 DFT 写成：

$$X[k] = \sum_{n=0}^{N-1} x[n]\,W_N^{kn}$$

要算出全部 $N$ 个 $X[k]$，你得对每个 $k$ 都跑一遍长度 $N$ 的求和——$N\times N=N^2$ 次乘加。$N=1024$ 就是一百多万次。

但这里面有大量**重复劳动**。$W_N^{kn}$ 这个数，只取决于乘积 $kn$ 模 $N$ 的余数（因为 $W_N$ 转一整圈就回到原点，$W_N^{N}=1$）。$k$ 和 $n$ 各跑 $0$ 到 $N-1$，$kn$ 的取值撞车撞得厉害——同一个 $W_N$ 的幂，在不同的 $(k,n)$ 组合里被反复算了无数遍。直接按定义算，等于对着一张早就填好的乘法表，每次都重新算一遍。FFT 要做的，就是把这张表的结构利用起来，算一次、复用多次。

### 2.2 分而治之：把 N 点拆成偶、奇两半

FFT 最经典的算法叫 **Cooley–Tukey**，核心思路一句话：**把一个长度 $N$ 的 DFT，拆成两个长度 $N/2$ 的 DFT。** 拆的方式是按下标的奇偶分组——偶数位的样本 $x[0],x[2],x[4],\dots$ 一组，奇数位的 $x[1],x[3],x[5],\dots$ 一组。

我们把这个拆分**推出来**，不要背。从定义出发，把求和按 $n$ 的奇偶劈成两摊（设 $N$ 是偶数）：

$$X[k] = \underbrace{\sum_{m=0}^{N/2-1} x[2m]\,W_N^{k(2m)}}_{\text{偶数位}} \;+\; \underbrace{\sum_{m=0}^{N/2-1} x[2m+1]\,W_N^{k(2m+1)}}_{\text{奇数位}}$$

现在动一下旋转因子的指数。偶数摊里是 $W_N^{k\cdot 2m}=W_N^{2km}$，而 $W_N^2 = e^{-j\frac{2\pi}{N}\cdot 2} = e^{-j\frac{2\pi}{N/2}} = W_{N/2}$——**两倍角的旋转因子，正好就是"半长" DFT 的旋转因子**。这一步是整个推导的关节，慢慢看：把 $N$ 点的旋转步子迈两格，等价于在 $N/2$ 点上迈一格。

奇数摊里把公共的一格提出来：$W_N^{k(2m+1)} = W_N^{k}\cdot W_N^{2km} = W_N^{k}\cdot W_{N/2}^{km}$。于是：

$$X[k] = \underbrace{\sum_{m=0}^{N/2-1} x[2m]\,W_{N/2}^{km}}_{\;=\;E[k]\;} \;+\; W_N^{k}\underbrace{\sum_{m=0}^{N/2-1} x[2m+1]\,W_{N/2}^{km}}_{\;=\;O[k]\;}$$

看这两摊求和——它们**各自就是一个长度 $N/2$ 的 DFT**：$E[k]$ 是偶数位样本的 $N/2$ 点 DFT，$O[k]$ 是奇数位样本的 $N/2$ 点 DFT。所以：

$$\boxed{\,X[k] = E[k] + W_N^{k}\,O[k]\,}$$

一个 $N$ 点 DFT，被我们拆成了"两个 $N/2$ 点 DFT，再用一个旋转因子 $W_N^k$ 把奇数摊转一下、加起来"。这就是分而治之的第一层。

### 2.3 一半的活儿凭空消失：$W_N^k$ 的对称性

到这里你可能会说：等等，$E[k]$ 和 $O[k]$ 只在 $k=0\dots N/2-1$ 上有定义（它们是 $N/2$ 点 DFT，只有 $N/2$ 个输出），可 $X[k]$ 要 $k=0\dots N-1$ 共 $N$ 个值。上半段 $k\ge N/2$ 怎么办？

这正是 FFT 白赚一半算力的地方。看旋转因子的一个漂亮性质——**转半圈就是取反**：

$$W_N^{k+N/2} = W_N^{k}\cdot W_N^{N/2} = W_N^{k}\cdot e^{-j\pi} = -\,W_N^{k}$$

而 $E[k]$、$O[k]$ 本身是 $N/2$ 点 DFT，天生以 $N/2$ 为周期（$E[k+N/2]=E[k]$）。把这两条代进上面的盒子公式，上半段就自动出来了：

$$X[k] \;\;=\; E[k] + W_N^{k}\,O[k]$$
$$X[k+N/2] = E[k] - W_N^{k}\,O[k]$$

看清楚了吗——**算 $X[k]$ 和 $X[k+N/2]$ 用的是同一对 $E[k]$、$O[k]$、同一个 $W_N^k O[k]$，只是一个取加、一个取减。** 一次乘法 $W_N^k O[k]$，喂出了两个频率 bin。这就是所谓的**蝶形运算 (butterfly)**：两个输入 $E[k]$、$O[k]$，一个旋转因子，一加一减吐出两个输出。画出来像只蝴蝶：

```
   E[k] ───────●───────→ X[k]      = E[k] + W·O[k]
                \     /
                 \   /
                  \ /
                   X               ● 处: 上面走 +, 下面走 -
                  / \
                 /   \
                /     \
  O[k] ──[×W_N^k]──●──→ X[k+N/2]   = E[k] - W·O[k]
```

原本上下半段要各算一遍求和，现在合并成一次蝶形。**这就是 $N^2$ 里"重复功"被抠掉的物理位置。**

### 2.4 一路拆到底：为什么复杂度落到 $O(N\log N)$

一层拆完，$E[k]$ 和 $O[k]$ 各自还是一个 $N/2$ 点 DFT——那就继续拿 2.2 的办法拆它们，拆成 $N/4$ 点。再拆成 $N/8$……一直拆到长度为 1 的 DFT。而长度为 1 的 DFT 是什么？$X[0]=x[0]$，**啥也不用算**。

拆到底一共拆了多少层？每层长度砍半，从 $N$ 砍到 1，正好 $\log_2 N$ 层。而每一层，不管拆到多细，把所有蝶形加起来，总共要处理 $N$ 个数据点、约 $N/2$ 次复数乘法。于是：

$$\text{总运算量} \approx \underbrace{\log_2 N}_{\text{层数}} \times \underbrace{\frac{N}{2}}_{\text{每层乘法}} = O(N\log_2 N)$$

对比一下这个加速有多离谱：

| $N$（点数） | DFT 直接算 $\sim N^2$ | FFT $\sim N\log_2 N$ | 快了约 |
|------------|----------------------|----------------------|--------|
| 1024 | ~100 万 | ~1 万 | 100 倍 |
| 8192 | ~6700 万 | ~10.6 万 | 630 倍 |
| 65536 | ~43 亿 | ~105 万 | 4000 倍 |

$N$ 越大，优势越夸张。**正是 FFT，才让实时频谱分析、实时语谱图、频域快速卷积（第 5 篇结尾埋的"时域昂贵卷积→频域廉价乘法"那个钩子）在你的笔记本上成为可能。** 没有它，数字音频里几乎所有频域处理都会慢到不可用。

### 2.5 用 N=4 具体走一遍蝶形

抽象公式看完，拿最小的例子把手弄脏。$N=4$，输入 $x=[x_0,x_1,x_2,x_3]$。旋转因子只有两个用得上：$W_4^0=1$，$W_4^1=e^{-j\pi/2}=-j$。

**第一层拆分**（按奇偶）：偶数位 $\{x_0,x_2\}$、奇数位 $\{x_1,x_3\}$，各做一个 2 点 DFT。

2 点 DFT 更简单，$W_2^0=1$、$W_2^1=-1$，就是一加一减：

$$E[0]=x_0+x_2,\quad E[1]=x_0-x_2 \qquad O[0]=x_1+x_3,\quad O[1]=x_1-x_3$$

**第二层合并**（用 2.3 的蝶形，$k=0,1$）：

$$X[0]=E[0]+W_4^0 O[0]=(x_0+x_2)+(x_1+x_3)$$
$$X[1]=E[1]+W_4^1 O[1]=(x_0-x_2)-j(x_1-x_3)$$
$$X[2]=E[0]-W_4^0 O[0]=(x_0+x_2)-(x_1+x_3)$$
$$X[3]=E[1]-W_4^1 O[1]=(x_0-x_2)+j(x_1-x_3)$$

数一下乘法：整个过程只有 $W_4^1=-j$ 这一次"真乘法"（乘 $\pm1$、乘 $\pm j$ 在实现里都是换符号/交换实虚部，几乎免费）。而直接按定义算 4 点 DFT 要 $4\times4=16$ 次复数乘。$N=4$ 已经省成这样，$N=1024$ 的差距就是那张表里的 100 倍。你可以拿 `np.fft.fft([1,2,3,4])` 核对上面四个式子，结果一模一样——因为 FFT 就是 DFT。

把 $N=8$ 的递归拆分画成一棵树，$\log_2 8=3$ 层一目了然——每往下一层长度砍半，最底层全是"啥也不用算"的 1 点 DFT，然后自底向上一层层用蝶形合并回去：

```
              8 点 DFT
             /         \        ← 第1层: 按奇偶拆
        偶{0,2,4,6}   奇{1,3,5,7}
         /      \       /      \    ← 第2层: 再各自按奇偶拆
     {0,4}   {2,6}   {1,5}   {3,7}
      / \     / \     / \     / \   ← 第3层: 拆到 2 点(=一次加减)
     0  4   2  6   1  5   3  7      ← 底: 1 点 DFT, 直接就是样本本身
     └──蝶形──┴──蝶形──┴──蝶形──┘   ← 然后逐层用蝶形合并上去
```

数一下：**层数 = $\log_2 N$，每层总共约 $N/2$ 次蝶形乘法**，两者相乘就是 $O(N\log_2 N)$ 的来历。这也顺带解释了 3.2 的 bit-reversal：最底层那排叶子的顺序 `0 4 2 6 1 5 3 7`，正是下标二进制位翻转后的排列。

## 三、FFT 的工程落地：帧长、bit-reversal、原地运算

数学讲完，落回你真正会碰到的工程细节——这些"为什么"，写实时音频代码时天天遇到。

### 3.1 为什么帧长、FFT 点数几乎清一色 2 的幂

看 2.4 的拆分：每一层要把长度砍成整齐的两半，才能一路 $N\to N/2\to N/4\to\dots\to1$ 拆到底。**只有 $N$ 是 2 的整数次幂（512、1024、2048、4096…），这个折半才能次次整除、拆得干干净净。** 这就是为什么音频分析里的帧长、FFT 点数几乎清一色是这些"整齐"的数——不是迷信，是 radix-2 FFT 的算法特性使然。

$N$ 不是 2 的幂也能做 FFT（现代库有混合基、Bluestein 等算法），但通常慢一截。所以工程上的常规操作是：把一帧样本**补零 (zero-padding)** 到最近的 2 的幂再送 FFT。补零不增加真实信息（$\Delta f=f_s/N$ 的物理分辨率不变），但让 bin 更密、频谱更平滑，且踩中最快的路径。

### 3.2 bit-reversal：拆到底之后，样本顺序被打乱了

2.5 里第一层就把输入按奇偶分了组：$[x_0,x_2 \,|\, x_1,x_3]$。再多拆几层，输入的读取顺序会被彻底打乱成一个特定排列——这个排列正好是**下标的二进制位翻转 (bit-reversal)**。

以 $N=8$ 为例，原始下标和它 3 位二进制翻转后的下标：

```
原下标  二进制   翻转    新位置
  0     000  →  000  →   0
  1     001  →  100  →   4
  2     010  →  010  →   2
  3     011  →  110  →   6
  4     100  →  001  →   1
  ...
```

实际的 FFT 实现，开头先按 bit-reversal 把输入重排一遍，之后每一层就能"就地相邻配对"做蝶形。这是一次性的 $O(N)$ 开销，相对 $O(N\log N)$ 的主体可以忽略。

### 3.3 原地运算：不额外开数组

2.3 的蝶形有个漂亮性质：$E[k]$、$O[k]$ 这**两个输入**算完，产出的 $X[k]$、$X[k+N/2]$ 这**两个输出**，正好可以写回这两个输入原来占的内存格子——因为算完就不再需要旧值了。于是整个 FFT 可以**原地 (in-place)** 做，只用输入那一块内存，不额外开新数组。对内存紧张的嵌入式/DSP 芯片，这一条很关键。

### 3.4 你永远不用自己写 FFT

上面这些（拆分、bit-reversal、原地蝶形）是"引擎盖下面"的事。**实际写代码时，你永远不需要手写 FFT**——`numpy.fft.fft` / `numpy.fft.rfft` 底层就是高度优化的 FFT 实现（实信号用 `rfft` 更快，只算正频率那一半）。知道原理是为了会选参数、会估成本，不是为了造轮子。

```python
import numpy as np

x = np.random.randn(1024).astype(np.float64)   # 一帧 1024 点实信号
X = np.fft.rfft(x)                              # 底层就是 FFT, O(N log N)
freqs = np.fft.rfftfreq(1024, d=1/16000)        # 每个 bin 的频率(第12篇的 f_s/N)
print(X.shape, freqs.shape)                     # (513,) (513,)  实信号只need一半
```

> **实时按帧的成本账**：$f_s=16$ kHz、帧长 $N=512$、帧移 $128$（75% 重叠）时，每秒约 $16000/128=125$ 帧，每帧一次 512 点 FFT（约 $512\times9\approx4600$ 次乘加）。一秒总共几十万次乘加——现代 CPU 眨眼的事。**这就是"慢"被 FFT 解决之后的世界：逐帧 FFT 便宜到可以随便用，于是我们敢把整段声音切成几百帧、每帧都做一次。** 这正好为下面的 STFT 铺好了路。

## 四、承上启下：一次 FFT 只是一张快照，我们需要连拍

FFT 把"慢"解决了。现在回到第一节的第二道坎：**糊**。

问题的根源，第 7 篇拆棱镜那节已经点破：**一次 FFT 天然是"无时间"的。** 你给它一段 1 秒音频，它告诉你"这 1 秒里总共有哪些频率、各多强"，但**绝口不提这些频率是什么时候出现的**。对一个稳定不变的音（持续的 440 Hz）这没问题；可语音、音乐里频率时刻在变，把整句拍成一张频谱，等于把开头和结尾的频率全叠在一起——一团糨糊。

解法朴素得近乎笨：**既然一次 FFT 只能给一张"快照"，那我就连拍。** 把长音频切成许多短小的片段（每片短到可以认为"这一小段里频率基本没变"），对**每一片**单独加窗、做 FFT，得到那一小段的频谱；再把这些频谱**按时间顺序一列一列排好**——横轴时间、纵轴频率、颜色深浅表示能量——一张随时间流动的频率地图就出来了。

这个"切片 + 逐片 FFT"的过程，就是**短时傅里叶变换 (Short-Time Fourier Transform, STFT)**；它产出的那张二维彩色图，就是**语谱图 (Spectrogram)**。第 3 节末尾那笔成本账说的正是它：因为有了 FFT，逐帧做几百次 FFT 才便宜到可行。

## 五、STFT 的数学：一个加窗 DFT，沿时间轴重复很多次

### 5.1 把定义逐字翻译成大白话

STFT 写成公式，就是把第 12 篇的 DFT 加上"从第 $m$ 帧起点开始、乘上窗 $w$"：

$$X[m, k] = \sum_{n=0}^{N-1} x[n + mR]\,w[n]\,e^{-j\frac{2\pi}{N}kn}$$

别被吓到，逐项翻译就是大白话：

- $m$：**第几帧**（第几张快照），决定这一列落在时间轴哪里；
- $k$：**第几个频率 bin**，和第 12 篇一样，对应频率 $f_k=k\cdot f_s/N$；
- $R$：**帧移 (hop size)**，相邻两帧起点隔多少个采样——决定连拍的"帧率"；$x[n+mR]$ 就是"把窗滑到第 $m$ 帧的位置去取那 $N$ 个样本"；
- $w[n]$：**窗函数**（第 12 篇讲过，压泄漏用的，STFT 里几乎必加）；
- 里层那个求和：**就是第 12 篇的 DFT，一字没变。**

所以 STFT 没有任何新数学。用一句话锁死它：

> **关键认知**：STFT = "**加窗 DFT，沿时间轴重复很多次**"。里层永远是那个你已经熟悉的 DFT/FFT；外层只是把窗一帧一帧往右滑。$X[m,k]$ 是个二维数组——一维是时间（帧号 $m$），一维是频率（bin 号 $k$）——把它的幅度 $|X[m,k]|$ 画成图，就是语谱图。

### 5.2 两个别混的独立旋钮：窗长 $N$ 和帧移 $R$

这里有个新手最容易搅在一起的坑，必须掰开：**$N$ 和 $R$ 是两个完全独立的参数，管两件不同的事。**

- **窗长 $N$（= FFT 点数）管"频率轴"**：它决定频率分辨率 $\Delta f=f_s/N$（第 12 篇那条换算原样搬过来），以及每一帧覆盖多长时间（$N/f_s$ 秒）。
- **帧移 $R$ 管"时间轴的步进"**：相邻两列在时间上隔 $R/f_s$ 秒。$R$ 越小，时间轴上采样越密、相邻帧重叠越多、图越平滑，代价是帧数更多、算得更慢。

举个具体的：$f_s=16$ kHz、$N=512$、$R=128$。那么频率分辨率 $\Delta f=16000/512=31.25$ Hz（由 $N$ 定），每一帧覆盖 32 ms（由 $N$ 定），而相邻两列在时间上只隔 $128/16000=8$ ms（由 $R$ 定）。**注意：帧覆盖 32 ms，但时间步进只有 8 ms——这不矛盾，因为相邻帧重叠了 $(512-128)/512=75\%$。** 窗长和帧移各调各的，别把"频率分得多细"和"时间走得多密"这两件事混成一个。

### 5.3 绕不开的硬约束：时间清楚，频率就糊（测不准）

第 12 篇埋的那个权衡，现在换了副更狠的面孔回来找你算账。

窗长 $N$ 一调，两件互相打架的事同时被决定：

- **窗越长**（$N$ 大）→ 频率分辨率越高（$\Delta f=f_s/N$ 越小，谐波看得越细），**但**这一帧覆盖的时间越长（$N/f_s$ 越大），"这一小段里频率没变"的假设越站不住，快速变化的瞬态被抹平——**时间糊**。
- **窗越短**（$N$ 小）→ 时间定位越准（能看清爆破音、瞬态的精确时刻），**但**频率分辨率越差（$\Delta f$ 变大，谐波挤成一团分不开）——**频率糊**。

这不是工程师偷懒，也不是算法不够好——它是**物理定律级别的硬约束**，本质是**时频不确定性原理**（和量子力学里那个测不准是同一套数学）。一段信号在时间上越集中，它的频谱在频率上就必然越铺开，反之亦然。二者的乘积有个下限，你不可能同时把"某频率出现在哪个精确时刻"两件事都测得无限准。

> **关键认知**：时频取舍**不是工程妥协，是数学硬限制**。给你再强的 CPU、再牛的算法，也逃不掉——窗长一选，你就在"频率看得清"和"时间看得清"之间站了队。这条约束是 STFT 一切参数设计的地基。

所以做语谱图永远在选边站，语音学给这两种选择起了名字：

| 你想看清什么 | 该用 | 名字 | 图看起来 |
|-------------|------|------|---------|
| 音高、谐波、共振峰的精细结构 | **长窗**（2048~4096 点） | 窄带 (narrowband) | 横向谐波纹路清晰，瞬态发糊 |
| 爆破音、节奏、瞬态的精确时刻 | **短窗**（256~512 点） | 宽带 (wideband) | 竖直瞬态锐利，谐波糊成竖条 |

没有哪个更好，只有"你这次想看什么"。第七节的代码会让你亲眼看到这两张图长得有多不一样。

## 六、等等，"语谱图 = 声音的照片"这个比喻会害你

很多教程一句"语谱图就是声音的照片"打发过去。这个比喻能起步，但停在这儿会栽跟头，得主动拆掉它。

**照片有一个客观、唯一的清晰度**——同一个场景拍出来就是那个样子，最多是相机好坏。可语谱图不是。同一段声音，**你换个窗长，会得到长得完全不同的两张图**：长窗那张横纹密布、竖直的瞬态糊成一片；短窗那张竖直边缘锐利、横向谐波却糊成宽带。到底哪张是这段声音"真实的样子"？**都是，也都不是。** 语谱图不是声音的客观照片，而是**你隔着一副特定"镜片"（窗长、窗型、帧移）去看声音的结果**——镜片一换，看到的就变。

更要命的是第二点：**照片可以无限放大看清细节，语谱图不行。** 5.3 那条测不准原理是焊死的天花板——你没法同时把时间和频率都看清。这不是分辨率不够、买个更好的"相机"就能解决；再强的算力也突破不了。所以语谱图更像**一张被物理定律限制了清晰度、且清晰度取向可调**的东西，而不是一张所见即所得的照片。

> **比喻的边界**：把语谱图当"照片"，会让你误以为它客观、唯一、能无限放大。真相是——它是**带着一副可调镜片、且镜片本身有物理上限**的观察结果。读语谱图时永远先问一句："这张图用的什么窗长？"不然你可能把"镜片造成的模糊"当成"声音本身的性质"。

## 七、STFT 的工程落地：窗、重叠、OLA 与实时按帧

这一节全是"驱动味"的实操细节——真写实时 STFT 时，坑都在这儿。

### 7.1 为什么要加窗、用 Hann/Hamming

第 12 篇讲过泄漏：DFT 假设你给的这段首尾相接、无限循环，可切出来的帧几乎不可能正好是整数个周期，接缝处的突变会把能量漏到邻近 bin。STFT 把长音频硬切成几百帧，**每一帧都是一次这样的"硬切"**——如果直接拿矩形窗（等于不加窗）去截，每帧首尾都有突变，泄漏严重，语谱图会糊上一层"栅栏"噪底。

解法就是给每帧乘一个两头平滑压到 0 的**窗函数**，最常用 **Hann**（升余弦）和 **Hamming**：

$$w_{\text{Hann}}[n] = 0.5\left(1-\cos\frac{2\pi n}{N-1}\right)$$

它把帧两端渐渐拉到 0，接缝处不再有突变，泄漏被压下去。代价是主瓣变宽（谱线略粗）——又是一次取舍，但对语谱图这点代价换来干净的底噪，值。Hann 是语音里的默认选择，`np.hanning(N)` 一句就有。

### 7.2 帧移、重叠与 50%/75%

**帧移 $R$ 通常取窗长的 25%~50%**（即相邻帧重叠 50%~75%）。为什么必须重叠？因为 Hann 窗把每帧两端压到了 0——如果帧首尾相接不重叠（$R=N$），那些被窗压没的样本就再也没被任何一帧"看清"过，时间轴上会出现周期性的能量塌陷。让帧重叠，一帧的边缘正好落在相邻帧的中心，谁也不被漏掉。

### 7.3 COLA：想从语谱图变回声音，重叠必须"恰好铺满"

如果你只是**画**语谱图，上面这些够了。但很多任务（降噪、变声、AEC）是在 STFT 域改完，再**逆 STFT 拼回波形**——这一步叫**重叠相加 (Overlap-Add, OLA)**：把每帧逆 FFT 得到的时域片段，按各自的位置叠回时间轴、相加。

要让 OLA 拼出来的波形不失真（没有周期性的忽大忽小），窗和帧移必须满足一个约束：**所有帧的窗，错开 $R$ 叠加起来，处处等于常数**——这叫 **COLA (Constant Overlap-Add)** 约束。写成式子：

$$\sum_{m} w[n - mR] = \text{常数}, \quad \forall n$$

直觉上就是"所有窗叠起来要把时间轴均匀铺满，不能有缝也不能有隆起"。Hann 窗在 50%、75% 重叠时正好满足 COLA——这也是这两个重叠率成为业界默认的深层原因，不只是"重叠多点更平滑"这么随意。**只分析不重建时可以不管 COLA；一旦要 OLA 重建，选错窗/帧移，声音会带上周期性的调制噪声。**

### 7.4 实时按帧：ring buffer 一帧一帧喂

回到你熟悉的驱动层。声卡不会一次把整段音频给你，而是每隔几毫秒交来一小块（几十~几百个样本）。实时 STFT 的标准做法，正是第 5 篇讲过的**环形缓冲 (ring buffer)**：

- 维护一个长度 $N$ 的 ring buffer，新样本源源不断写进去；
- 每当**攒够 $R$ 个新样本**，就从 buffer 里取出最近 $N$ 个样本（含与上一帧重叠的 $N-R$ 个旧样本），加窗、做一次 $N$ 点 FFT，产出语谱图的新一列；
- 重叠的那 $N-R$ 个样本不重复读入、只在 buffer 里留着——这正是"重叠"在代码里的落地方式。

```python
import numpy as np

class StreamingSTFT:
    """实时按帧 STFT：ring buffer 攒够一个 hop 就吐一列频谱。"""
    def __init__(self, n_fft=512, hop=128):
        self.N, self.R = n_fft, hop
        self.win = np.hanning(n_fft)
        self.buf = np.zeros(n_fft)      # 长度 N 的历史窗
        self.filled = 0                 # 距离下一帧还差多少新样本

    def push(self, block):              # 声卡送来的一小块样本
        cols = []
        for s in block:
            self.buf = np.roll(self.buf, -1)   # 示意: 左移腾出尾部(实际用环形指针)
            self.buf[-1] = s
            self.filled += 1
            if self.filled >= self.R:          # 攒够一个 hop
                self.filled = 0
                spec = np.fft.rfft(self.buf * self.win)   # 加窗 + FFT = 一列
                cols.append(np.abs(spec))
        return cols
```

> **驱动视角的坑**：ring buffer 的读写指针差一格，整张语谱图就在时间轴上错位；帧边界和声卡回调块大小对不齐时（比如回调块 480 样本、hop 128 除不尽），要么内部再缓冲、要么帧率会抖。这类"差一个样本 / 对不齐"的 bug，和第 5 篇卷积延迟线里的对齐坑是同一类病。

## 八、怎么读懂一张语谱图

语谱图是语音算法工程师的"心电图"，先学会读它。三根轴：

- **横轴 = 时间**：从左到右，声音怎么随时间展开（就是帧号 $m$ 换算成秒）。
- **纵轴 = 频率**：从下到上，低频在下、高频在上（就是 bin 号 $k$ 换算成 Hz）。
- **颜色 = 能量**：越亮/越暖表示该时刻该频率的能量越强（通常用 dB）。

拿到一张人声语谱图，你能一眼读出这些：

- **底部一条条水平、平行的亮纹**：浊音（元音、有调音）的**谐波**——基频及其整数倍。纹路密集平行，间距就是基频 $f_0$。
- **纹路整体上下滑动**：音高在变，这就是语调、声调（中文四声在语谱图上是肉眼可见的滑动轨迹）。
- **某几个频率区域持续偏亮的"团"**：**共振峰 (formant)**，由声道形状决定，是区分 a/i/u 等元音的关键。
- **竖直、覆盖整个频率范围的宽带亮条**：爆破音、辅音或瞬态（"p"、"t" 的冲击），能量瞬间铺满全频段。
- **高频区一片模糊的"雾"**：擦音（"s"、"sh"）或噪声，没有清晰谐波结构。

**你在 Praat、Audition、各种语音标注工具里看到的那张彩图，就是这么来的——一列列加窗 FFT 拼出来的。** 语音识别、说话人识别、声纹、TTS 声码器，绝大多数现代语音算法的第一步，都是先把波形变成这张（或它的近亲梅尔谱）图——第 17 篇讲 MFCC 时，第一步"分帧 + 加窗 + FFT"就是这里的 STFT。

## 九、代码实战：把一段真实人声变成语谱图

理论到此为止，动手。下面这段代码读入工作目录里的 `Test-voice.wav`，用**长窗**和**短窗**各画一张语谱图，让你亲眼看到 5.3 那条"时间-频率"取舍。STFT 我们手写（揭开黑箱，看清"逐帧加窗 + rfft"就这么回事），生产里换成 `scipy.signal.stft` 原理一模一样。

```python
import numpy as np
import matplotlib.pyplot as plt
from scipy.io import wavfile          # 用 scipy 读 wav, 不依赖 soundfile

# ---------- 读入真实人声 ----------
fs, data = wavfile.read("Test-voice.wav")
if data.ndim == 2:                    # 立体声 -> 单声道
    data = data.mean(axis=1)
x = data.astype(np.float64)
x /= np.max(np.abs(x)) + 1e-12        # 归一化到 [-1, 1]
x = x[int(3.0*fs): int(3.0*fs) + int(2.5*fs)]   # 截中间 2.5s 清晰语音

# ---------- 手写 STFT: 逐帧加窗 + FFT ----------
def stft(sig, n_fft, hop, fs):
    win = np.hanning(n_fft)                          # Hann 窗, 压泄漏(7.1)
    frames = []
    for start in range(0, len(sig) - n_fft, hop):
        seg = sig[start:start + n_fft] * win         # 取一帧 + 加窗
        frames.append(np.abs(np.fft.rfft(seg)))      # 这一帧的 FFT(=DFT)
    S = np.array(frames).T                           # 每一列 = 一帧
    S_db = 20 * np.log10(S / (S.max() + 1e-12) + 1e-6)
    freqs = np.fft.rfftfreq(n_fft, d=1/fs)           # bin -> Hz (第12篇 f_s/N)
    times = np.arange(S.shape[1]) * hop / fs         # 帧号 -> 秒
    return S_db, freqs, times

# ---------- 长窗 vs 短窗, 各画一张 ----------
fig, ax = plt.subplots(1, 2, figsize=(13, 5))
configs = [
    (2048, "Long frame N=2048 (~46ms): fine freq, blurry time  [narrowband]"),
    (256,  "Short frame N=256 (~6ms): sharp time, coarse freq  [wideband]"),
]
for a, (n_fft, name) in zip(ax, configs):
    S_db, freqs, times = stft(x, n_fft=n_fft, hop=n_fft // 4, fs=fs)
    im = a.pcolormesh(times, freqs, S_db, shading="auto",
                      vmin=-70, vmax=0, cmap="magma")
    a.set_title(name, fontsize=9)
    a.set_xlabel("Time (s)"); a.set_ylabel("Frequency (Hz)")
    a.set_ylim(0, 5000)
    fig.colorbar(im, ax=a, label="dB")

plt.tight_layout()
plt.show()
```

![同一段真实人声的两张语谱图：左为长窗（N=2048），横向谐波纹路细密清晰但瞬态在时间上发糊；右为短窗（N=256），竖直的语音起始/爆破瞬态锐利但谐波纹路糊成宽带——时间与频率分辨率此消彼长](fig_13_1_1.png)

**对比两张图，取舍一目了然**：

- **长窗（左，$N=2048$，$\Delta f\approx 21.5$ Hz）**：横向那一条条平行的**谐波纹路又细又清晰**（频率分辨率高，浊音的基频与共振峰结构看得清清楚楚），但每帧覆盖 46 ms，辅音、爆破那些快速瞬态在**时间上被抹糊**了。
- **短窗（右，$N=256$，$\Delta f\approx 172$ Hz）**：语音的起始、爆破这些**瞬态在时间轴上收得很锐**（时间定位准），但频率格子粗了 8 倍，横向谐波**糊成一片宽带**，分不开了。

同一段声音、同一套 FFT，只是窗长不同，就给你两张观感截然不同的图——这就是第六节说的"镜片一换，看到的就变"，也是为什么调语谱图参数是门手艺活。

> **想直接用生产 API**：把手写的 `stft` 换成 `from scipy.signal import stft as sp_stft`，一句 `f, t, Z = sp_stft(x, fs, nperseg=n_fft, noverlap=n_fft*3//4)` 就得到复数 STFT 矩阵 `Z`，`np.abs(Z)` 取幅度画图，原理和上面手写的一模一样。要重建波形则用配套的 `scipy.signal.istft`（内部就是 7.3 的 OLA，默认窗满足 COLA）。

## 十、这在音频工程里，到底解决了什么问题

| 场景 | 背后就是 FFT / STFT / 语谱图 |
|------|------------------------------|
| **语音识别 / 关键词唤醒的前端** | 波形先经 STFT 转成语谱图（或梅尔谱、MFCC），再喂给声学模型——几乎所有现代 ASR 的第一步，见第 17、18 篇 |
| **声纹 / 说话人识别** | 说话人的共振峰、谐波结构在语谱图上有个体特征，是提取声纹嵌入的基础 |
| **降噪 / 回声消除** | 在 STFT 域逐帧逐 bin 估噪、施加增益，处理完再逆 STFT（OLA）拼回波形；第 19 篇的 AEC 频域实现即此 |
| **音高检测 / 自动修音 (Auto-Tune)** | 从每帧频谱找基频，逐帧修正后重建——修音软件的核心流程 |
| **音乐可视化 / 频谱分析仪** | 播放器里那排随音乐跳动的彩色柱，就是实时 STFT 的一列 |
| **快速卷积混响** | 第 5 篇那 500 亿次乘加的时域卷积，靠 FFT 搬到频域做逐点乘法，才在笔记本上实时可跑 |

> **一句话记住**：现代语音/音频算法极少直接啃原始波形，绝大多数都先用 STFT（底层靠 FFT 提速）把声音摊成语谱图这张"二维图像"，再在图上做文章。看懂语谱图、会调它的时频取舍，是转行做语音算法的入场券。

## 十一、埋一个钩子：想"设计"一个滤波器，光会分析还不够

到这里，你已经能把声音**分析**得明明白白了——FFT 把频谱算得飞快，STFT 把它画成随时间流动的语谱图。但工程师的活儿不止是"看",更要"改":我想做一个数字混响、一个梳状滤波器、一段均衡器，该怎么**设计**它们？

设计滤波器时，你会立刻撞上一堆新问题：这个滤波器稳不稳定（会不会自激啸叫）？它在各个频率上到底放大还是衰减？反馈系数怎么定？光靠语谱图回答不了——你需要一张能一眼看穿数字滤波器"性格"的地图。

那张地图，就是**Z 变换**的极点零点图。它之于数字信号，正如拉普拉斯变换之于模拟信号（还记得第 11 篇拉普拉斯埋下的钩子吗）。下一篇（第 14 篇），我们就去拿这张导航图。

## 本篇小结

- **FFT**：算 DFT 的高速引擎，**结果与 DFT 完全相同**，不是新变换、不是近似。靠"按奇偶折半 → $X[k]=E[k]+W_N^k O[k]$、$X[k+N/2]=E[k]-W_N^k O[k]$（蝶形）→ 一路递归 $\log_2 N$ 层"，把 $O(N^2)$ 砍到 $O(N\log_2 N)$。
- **工程侧（FFT）**：帧长取 2 的幂才好折半；bit-reversal 重排输入；蝶形可原地运算；`numpy.fft` 底层就是它，你不用自己写。逐帧 FFT 便宜到可随便用——这才有了 STFT。
- **STFT**：= "加窗 DFT，沿时间轴重复很多次"。$X[m,k]=\sum_n x[n+mR]w[n]e^{-j2\pi kn/N}$，里层永远是 DFT。产物是语谱图：横轴时间、纵轴频率、颜色能量。
- **两个独立旋钮别混**：窗长 $N$ 管频率轴（$\Delta f=f_s/N$、帧覆盖 $N/f_s$）；帧移 $R$ 管时间步进与重叠。
- **测不准是硬约束不是妥协**：窗长一选，就在"频率清楚（长窗/窄带）"和"时间清楚（短窗/宽带）"之间站队，二者不可兼得。
- **拆比喻**："语谱图=照片"会骗你——它不是客观唯一的（换窗长就变样），也不能无限放大（测不准封顶）。它是隔着一副可调、且有物理上限的镜片看声音的结果。
- **工程侧（STFT）**：Hann/Hamming 窗压泄漏；50%/75% 重叠 + COLA 才能 OLA 无失真重建；实时用 ring buffer 攒够一个 hop 喂一帧，当心对齐坑。
