# 第 12 篇｜从连续到离散：DTFT 与 DFT，理论与现实的桥

> 一句话核心直觉：真正的傅里叶变换处理的是**无限长的连续信号**，可你的电脑手里只有**有限长的一串数字**——DFT 就是那个"缩水但能真正被算出来"的务实版本，代价是它会带来泄漏，所以我们必须加窗。

---

## 一、先认清一个尴尬的落差

前面几篇（第 6～9 篇）我们把频域的门推开了：任何声音都能拆成一堆正弦的叠加，傅里叶变换 $X(f)=\int_{-\infty}^{+\infty}x(t)e^{-j2\pi ft}\,dt$ 就是那台"拆分机"。

这台机器很美，但它有两个前提，你的电脑一个都满足不了：

- 它吃的是 $x(t)$，一个**连续**的、时间上没有缝隙的函数；可电脑里只有采样点 $x[0], x[1], x[2], \dots$，一串离散的数字。
- 它的积分从 $-\infty$ 到 $+\infty$，要求信号**无限长**；可你录的音频再长也是有限的，几秒钟、几十万个采样，到头了。

所以那个课本上的公式，电脑一行都跑不了。它是数学家的理想，不是工程师的工具。

这一篇，就是要架一座桥：从"理论上正确但算不了"的连续傅里叶变换，一步步走到"能真正在 NumPy 里跑出来"的 DFT。走完这段路，你才算真正拿到了分析声音的那把手术刀。

---

## 二、两步妥协，从理论走到现实

从连续傅里叶变换到电脑能算的东西，中间隔着两步妥协。把这两步想明白，后面所有的坑（泄漏、分辨率、加窗）就都是水到渠成。

### 妥协一：时间离散化 → DTFT

第一刀，砍在时间轴上。我们没有连续的 $x(t)$，只有采样点 $x[n]$。把积分换成求和，就得到 **DTFT（离散时间傅里叶变换）**：

$$X(e^{j\omega}) = \sum_{n=-\infty}^{+\infty} x[n]\,e^{-j\omega n}$$

注意看它的产出：输入是**离散**的采样点，但输出 $X(e^{j\omega})$ 关于频率 $\omega$ 仍然是**连续**的——它是一条光滑的曲线，横轴上有无穷多个频率点。

这就带来第二个尴尬：电脑没法存一条"连续曲线"，它只能存有限个数字。而且这个求和还是从 $-\infty$ 到 $+\infty$。所以 DTFT 依然算不了，它只是理论上的中间站。

### 妥协二：频率也离散化 + 信号截断 → DFT

第二刀，砍在频率轴上，顺便把信号也截短。

- 信号只取有限的 $N$ 个采样点（就是你实际录到的那一段）；
- 频率轴也别要"连续曲线"了，只在 $N$ 个等间隔的频率点上取值。

这就得到了电脑真正在算的 **DFT（离散傅里叶变换）**：

$$X[k] = \sum_{n=0}^{N-1} x[n]\,e^{-j\frac{2\pi}{N}kn}, \qquad k=0,1,\dots,N-1$$

现在，输入是 $N$ 个数，输出也是 $N$ 个数，求和范围是有限的 $0$ 到 $N-1$。**没有无穷，没有连续，全是有限个数字。** 这才是一台电脑能咽下去的东西。

> **关键认知**：DFT 不是一个"新变换"，它是被两次现实约束（时间离散、频率离散且信号有限长）逼出来的傅里叶变换的**可计算近似**。它的每一个"缺陷"，都能追溯到这两次妥协。理解这一点，比背下公式重要一百倍。

把这几个变换放一张表里，一眼看清家谱：

| 变换 | 时间 | 频率 | 电脑能算吗 |
|------|------|------|-----------|
| 连续傅里叶变换 (FT) | 连续、无限长 | 连续 | 不能 |
| DTFT | 离散、无限长 | **连续** | 不能（频率是连续曲线） |
| **DFT** | 离散、**有限长** | **离散** | **能** |

## 三、DFT 的每根"频率格子"到底代表多少 Hz

DFT 吐出 $N$ 个数 $X[0], X[1], \dots, X[N-1]$，每一个都对应一个具体频率，工程上把它们叫**频率 bin（频段/频率格子）**。这里藏着两个你必须刻进肌肉记忆的换算。

设采样率是 $f_s$，你取了 $N$ 个采样点做 DFT，那么：

- **第 $k$ 个 bin 对应的频率**是 $f_k = k\cdot\dfrac{f_s}{N}$；
- **相邻两个 bin 的频率间隔**（也就是**频率分辨率**）是 $\Delta f = \dfrac{f_s}{N}$。

第二条是重点中的重点。$\Delta f = f_s/N$ 意味着：**你分析的这段信号越长（$N$ 越大），频率格子就越细密，你能分辨出的频率差异就越小。**

举个音频里的实感：采样率 $f_s = 16000$ Hz。

- 如果你只取 $N=512$ 个点（约 32 毫秒），$\Delta f = 16000/512 \approx 31.25$ Hz。也就是说，两个只差 20 Hz 的音，在频谱上会挤进同一个格子，你根本分不开。
- 如果你取 $N=8192$ 个点（约 512 毫秒），$\Delta f \approx 1.95$ Hz，此时连相邻半音里的细微差别都看得清清楚楚。

这就是那句核心权衡的由来：**想要更高的频率分辨率，就得用更长的信号段。** 别急，下一篇讲语谱图时你会看到硬币的另一面——用太长的段，时间上就糊了。这对矛盾是 STFT 一切设计的核心。

## 四、频谱泄漏：DFT 最容易坑你的那个"隐藏假设"

现在讲这篇最重要、也最反直觉的一件事。

DFT 只看你给它的那 $N$ 个采样点。但它内部其实偷偷做了一个假设：**它认为你给的这一段，会一模一样地无限循环下去，首尾相接，拼成一个无限长的周期信号。** 这不是可选项，这是 DFT 数学结构里写死的——频率离散化的另一面，必然对应时间上的周期延拓。

问题就出在"首尾相接"这四个字。

想象你截取了一段 440 Hz 的纯音。如果你截的这一段里**正好装下整数个周期**，那么把它首尾相接时，波形能严丝合缝地接上，循环出来还是一条完美的 440 Hz 正弦——DFT 分析它，能量会干净利落地全部落进 440 Hz 那一个 bin 里。

可现实中，你截出来的段几乎**不可能**正好是整数个周期。于是首尾接不上，接缝处出现一个突兀的跳变、一个"折角"。而一个带折角的波形，在傅里叶看来，绝不是单一频率——那个尖锐的跳变需要一大堆额外的频率成分才能拼出来。

**结果就是：本该集中在 440 Hz 一根线上的能量，"漏"到了周围一大片 bin 里，频谱底部拖出一群本不存在的"裙边"。** 这个现象就叫**频谱泄漏 (spectral leakage)**。

请记牢这个因果链，它是理解加窗的唯一钥匙：

> 信号非整数周期 → 周期延拓后首尾接缝处产生突变 → 突变含大量杂散频率 → 真实频率的能量泄漏到邻近 bin。

泄漏不是 DFT 算错了，它是"用有限长的段去分析、还被强行首尾相接"这个前提的必然副作用。既然病根在"接缝处的突变"，解药也就呼之欲出了。

---

## 五、加窗：给信号段的两头"抹上黄油"

既然泄漏来自首尾接缝处的突然跳变，那最朴素的想法就是：**能不能让信号段的开头和结尾都平滑地降到 0？** 这样无论怎么首尾相接，接缝处都是 $0$ 接 $0$，没有折角，也就没有那些杂散频率了。

这正是**加窗 (windowing)** 干的事。所谓窗，就是一条两头低、中间高的包络曲线 $w[n]$，我们把它逐点乘到信号段上：

$$x_w[n] = x[n]\cdot w[n]$$

你直接截取一段不加处理，其实等于乘了一个**矩形窗**（段内全是 1，段外全是 0）——正是这个"啪"一下切断的硬边界，制造了最严重的泄漏。而像**汉宁窗 (Hann)**、**汉明窗 (Hamming)** 这类平滑窗，两头都柔和地趋近于 0，把接缝处的突变抹平了。

天下没有免费的午餐。加窗压住了泄漏（旁瓣变矮），代价是让每根谱线变粗了一点（主瓣变宽）——相当于牺牲了一丁点频率分辨率，换来干净得多的频谱底噪。这个取舍，就是音频分析里为什么有那么多种窗函数可选的原因。

| 窗类型 | 主瓣（谱线粗细） | 旁瓣（泄漏/裙边） | 音频里的典型用途 |
|--------|----------------|------------------|-----------------|
| 矩形窗（不加窗） | 最窄 | 最严重 | 只在整数周期、或要极限分辨两个等强频率时 |
| 汉宁窗 (Hann) | 中等 | 低 | 语谱图、通用频谱分析的默认选择 |
| 汉明窗 (Hamming) | 中等 | 低（第一旁瓣更低） | 语音分析、共振峰提取 |
| 布莱克曼窗 (Blackman) | 较宽 | 极低 | 需要极干净底噪、能容忍分辨率损失时 |

## 六、代码实战：亲眼看见泄漏，再亲眼看着它被窗压下去

光说不练假把式。下面这段代码做一件事：拿一个**故意不是整数周期**的正弦，分别用矩形窗（不加窗）和汉宁窗做 DFT，把两张频谱叠在一起看。你会亲眼看到那片"裙边"是怎么被窗按下去的。

```python
import numpy as np
import matplotlib.pyplot as plt

fs = 16000          # 采样率 16 kHz
N  = 1024           # 分析段长度
f0 = 440.3          # 故意选一个"非整数周期"的频率(不是 fs/N 的整数倍)

# ---------- 造一段纯音 ----------
n = np.arange(N)
x = np.sin(2 * np.pi * f0 * n / fs)

# ---------- 1) 矩形窗(即不加窗,直接截断) ----------
X_rect = np.fft.rfft(x)                       # rfft 只返回正频率部分
freqs  = np.fft.rfftfreq(N, d=1/fs)           # 每个 bin 对应的真实频率(Hz)

# ---------- 2) 汉宁窗 ----------
w = np.hanning(N)
X_hann = np.fft.rfft(x * w)

# ---------- 转成分贝(dB),这样"裙边"才看得清 ----------
def to_db(X):
    mag = np.abs(X)
    return 20 * np.log10(mag / mag.max() + 1e-12)   # 归一化后取 dB

plt.figure(figsize=(10, 5))
plt.plot(freqs, to_db(X_rect), label="Rectangular (no window)", alpha=0.8)
plt.plot(freqs, to_db(X_hann), label="Hann window", linewidth=2)
plt.xlim(0, 2000)
plt.ylim(-100, 5)
plt.xlabel("Frequency (Hz)")
plt.ylabel("Magnitude (dB)")
plt.title("Spectral leakage: rectangular vs. Hann window (440.3 Hz tone)")
plt.legend(); plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.show()
```

![440.3 Hz 非整数周期正弦的频谱：矩形窗（不加窗）主峰两侧拖着缓降的泄漏裙边，汉宁窗把裙边压到几十 dB 以下，代价是主瓣略微变宽](fig_12_1_1.png)

**你会在图里看到两件事**：

1. 矩形窗那条曲线，在 440 Hz 主峰两侧拖着长长的、缓慢下降的"裙边"，一直漏到几百 Hz 开外都还有可观的能量——这就是泄漏。
2. 汉宁窗那条曲线，主峰稍微胖了一点点（主瓣变宽），但两侧的裙边被死死压到了几十 dB 以下——频谱底部瞬间干净了。

把 `f0` 改回 `fs/N` 的整数倍（比如 `f0 = 15 * fs / N`），你会看到矩形窗的裙边神奇地消失了——因为此时正好是整数周期，首尾严丝合缝。这个小实验，就是"泄漏来自非整数周期"这句话最直接的证据。

> **想进一步玩**：把 `x` 换成两个频率很接近、但强度悬殊的正弦叠加（比如 440 Hz 的强音 + 470 Hz 的弱音）。用矩形窗时，强音的裙边会把弱音彻底淹没；换汉宁窗后，弱音才会从裙边里"浮"出来。这就是为什么真实音频分析几乎总要加窗。

## 七、这在音频工程里，到底解决了什么问题

DFT 和加窗不是考试题，它们是你以后每天要打交道的工具的底层逻辑：

| 场景 | 背后就是 DFT + 加窗 |
|------|--------------------|
| **看一段声音的频谱** | 频谱分析仪、EQ 插件里那条实时跳动的频率曲线，本质就是不断对新来的信号段做加窗 DFT |
| **基频/音高检测** | 找出频谱里能量最高的 bin，$f_k = k\cdot f_s/N$ 反推出音高；分辨率不够就得加长 $N$ |
| **共振峰 (formant) 分析** | 语音元音的辨识依赖频谱包络的几个峰，泄漏会污染峰形，所以语音分析偏爱汉明窗 |
| **降噪 / 频域处理** | 把噪声段的频谱估计出来再从含噪信号里"减掉"，前提是频谱估得准——加窗直接影响估计质量 |

> **一句话记住**：你在任何音频软件里看到的那条频谱曲线，都不是"真实连续频谱"，而是**一段有限信号、加了某个窗、做了 DFT** 的结果。它带着分辨率的限制和加窗的取舍——看懂这些取舍，你才不会被频谱图骗。

## 八、埋一个钩子：DFT 很慢，而且一张图不够用

到这里你已经能算频谱了，但有两个问题正等在前面。

第一，**DFT 直接按定义算，很慢**。$N$ 个点的 DFT 要做大约 $N^2$ 次复数乘加。$N=8192$ 时就是六千多万次——想实时分析音频，这个开销扛不住。有没有一台"高速引擎"能把它加速到几乎白送？有，它叫 **FFT**。

第二，**一段声音只做一次 DFT，是不够的**。一句话、一首歌里，频率成分时时刻刻都在变；你把整段拍成一张频谱，等于把所有时刻的频率全糊成了一团，完全看不出"什么时候出现了什么频率"。可如果我把声音切成一小片一小片、逐片做 FFT 再拼起来呢？那张随时间流动的彩色图，就是**语谱图 (Spectrogram)**——正是下一篇（第 13 篇）要亲手做出来的东西。

而这一篇讲的频率分辨率与窗长的权衡，到那时会换一副面孔重新出现，逼着我们做出取舍。

---

## 本篇小结

- **连续傅里叶变换**理论完美但算不了：它要连续、无限长的信号。
- **DTFT**：把时间离散化，但频率仍是连续曲线，电脑还是存不下。
- **DFT**：再把频率离散化、信号截成有限长——$N$ 个数进、$N$ 个数出，这才是电脑真正在算的傅里叶变换。
- **频率分辨率** $\Delta f = f_s/N$：信号段越长，频率分得越细。
- **频谱泄漏**：DFT 假设信号首尾相接无限循环，非整数周期会在接缝处产生突变，把能量漏到邻近 bin。
- **加窗**：把信号段两头平滑压到 0，消除接缝突变、压住泄漏，代价是谱线略微变粗。
- **下一步**：FFT 给 DFT 提速，STFT 把频谱沿时间铺开——让声音"显形"成语谱图。
