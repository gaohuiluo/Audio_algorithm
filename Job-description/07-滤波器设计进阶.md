## 二、理论推导

推导路线：
1. 理想低通的冲激响应：为什么是 sinc，为什么它没法直接用。
2. 窗函数法：用窗截短 sinc，设计出 FIR。
3. 阶数怎么定：过渡带、阻带衰减的经验关系。
4. 双线性变换：模拟原型 → 数字 IIR 的桥梁。
5. biquad 与参数 EQ：亲手推系数公式。

### 2.1 理想低通的冲激响应：sinc 函数从哪来

我们想要一个"完美低通"：在频域上，截止频率 `fc` 以下增益为 1（完全通过），以上为 0（完全阻断）——一个**矩形**的频率响应。

那么它的**冲激响应** `h[n]` 长什么样？根据第 03 篇，时域和频域是一对傅里叶变换。所以理想低通的 `h[n]` = 矩形频响的**逆傅里叶变换**。这个逆变换算出来是一个 **sinc 函数**：

$$
h_{ideal}[n] = \frac{\sin(2\pi f_c n / f_s)}{\pi n} = 2\frac{f_c}{f_s}\,\text{sinc}\left(\frac{2 f_c n}{f_s}\right)
$$

**逐块拆解：**
- 这是个中间高、两边振荡衰减的波形（像水波纹），中心在 `n=0`。
- `fc/fs` 是归一化截止频率。
- **致命问题**：sinc 函数**无限长**（`n` 从 −∞ 到 +∞ 都有非零值），而且是**非因果**的（`n<0` 也有值，意味着"未来"影响"现在"）。

> 💡 **为什么"完美"反而不能用？——时频对偶的必然**：回忆第 06 篇——频域的"突然截断"（矩形）会对应时域的振荡拖尾。这里正是它的对偶：**频域一个完美的矩形（锐利边缘），对应时域一个无限长的 sinc（拖尾振荡）**。所以"频率上完美锐利"和"时间上有限长"不可兼得——又是一个测不准式的权衡。理想低通因为要频域绝对锐利，代价就是时域无限长，无法实现。

**这正是滤波器设计的核心矛盾**：我们想要接近理想的频响，但必须用**有限长**的 `h[n]` 去逼近那个无限长的 sinc。怎么"截短"这个 sinc 而尽量不破坏频响？——答案就是加窗。

### 2.2 窗函数法：用窗把 sinc 截短成 FIR

最朴素的想法：把 sinc 直接"砍两刀"，只保留中间 M 个样本（相当于乘一个矩形窗）。但第 06 篇告诉我们：**矩形截断会导致严重的频谱泄漏**——反映到滤波器上，就是频响出现大的**波纹 (ripple)** 和不够深的阻带衰减（这就是第 03 篇实验三那个"波纹"的真身！）。

**窗函数法的解法**：不用矩形硬砍，而是用一个平滑的窗（Hann、Hamming、Blackman、Kaiser）去乘 sinc：

$$
h[n] = h_{ideal}[n] \cdot w[n], \qquad n = 0, 1, \dots, M-1
$$

（同时把 sinc 中心平移到 `n=(M-1)/2` 使其因果化——这就是第 04 篇说的 FIR 那个 `(M-1)/2` 固定群延迟的由来！）

**逐块拆解 why：**
- 平滑的窗让 sinc 的两端**渐渐淡出**到 0，而不是突然砍断。
- 于是频响的波纹被压低、阻带衰减加深——**代价是过渡带变宽**（又是"泄漏 vs 分辨率"权衡，和第 06 篇一模一样）。
- 不同窗给不同的"阻带衰减 vs 过渡带宽"折中：
  - 矩形窗：过渡带最窄，但阻带衰减只有约 21dB（波纹大，几乎不用）。
  - Hamming：阻带约 53dB，过渡带适中，**常用**。
  - Blackman：阻带约 74dB，过渡带较宽。
  - **Kaiser 窗**：有个参数 β 可以**连续调节**这个折中，最灵活，工程首选。

> 💡 **一句话抓住本质**：**FIR 窗函数法 = "理想 sinc" 乘 "一个窗"。** 窗的形状决定了你的滤波器有多好（阻带多深）和有多"贵"（过渡带多宽、需要多少阶）。第 06 篇你用窗抑制分析时的泄漏，这里你用同一个窗抑制滤波器设计时的波纹——**同一套数学，两处应用。**

### 2.3 阶数怎么定：过渡带与阻带的经验关系

客户说"过渡带要窄、阻带衰减要深"，你要多少阶 M？有个非常实用的经验公式（以 Kaiser 窗为例，Kaiser 自己给出的估计）：

$$
M \approx \frac{A - 8}{2.285 \cdot \Delta\omega}
$$

**逐块拆解：**
- `A`：要求的阻带衰减（dB）。要求越深，M 越大。
- `Δω`：过渡带宽度（归一化角频率）。要求越窄，M 越大。
- 两者都"贪心"（深且窄），M 就爆炸增长。

> 🔧 **驱动直觉**：这个公式直接关系到你的**算力和延迟预算**。客户要"60dB 阻带 + 100Hz 极窄过渡带"，代入一算可能要几百阶 FIR——每样本几百次乘加、群延迟几百样本（几毫秒到十几毫秒延迟）。这时你就有了和客户/产品谈判的**定量筹码**："要这么陡的 FIR，延迟会到 X ms、算力要 Y MIPS；要么放宽指标，要么改用 IIR 牺牲相位换低延迟。" **滤波器设计不是数学游戏，是算力/延迟/质量的工程谈判，而这个公式是你的谈判底牌。**

### 2.4 双线性变换：把模拟滤波器"数字化"成 IIR

FIR 用窗函数法从零设计。IIR 则走另一条聪明的路：**不从零开始，而是站在模拟滤波器的肩膀上。**

模拟（连续）滤波器领域，几十年来积累了成熟的"原型"：**巴特沃斯**（最平坦）、**切比雪夫**（更陡但有波纹）、**椭圆**（最陡）。它们的传递函数 `H(s)`（`s` 是模拟域的复频率，来自拉普拉斯变换）都是现成的。

**双线性变换 (Bilinear Transform)** 就是把模拟 `H(s)` 变成数字 `H(z)` 的桥梁，核心是一个变量代换：

$$
s = \frac{2}{T}\cdot\frac{1 - z^{-1}}{1 + z^{-1}}
$$

**逐块拆解 why 这个代换：**
- 它把模拟域的整个频率轴（`s` 平面的虚轴，0 到 ∞）**压缩映射**到数字域的单位圆上（0 到 π）。
- **好处**：模拟域稳定的滤波器（极点在左半平面），映射后一定数字稳定（极点在单位圆内）——**稳定性自动保证**。这是它比其他变换法优越的关键。
- **代价——频率扭曲 (frequency warping)**：这个映射是非线性的，高频被"压缩"了。所以模拟原型的截止频率和你想要的数字截止频率对不上，需要**预畸变 (pre-warping)** 校正：先把目标数字频率反算成对应的模拟频率，用它设计模拟原型，变换后就正好落在目标数字频率上。

> 💡 **大白话**：双线性变换就像把一张"模拟世界的地图"投影到"数字世界的球面"上。投影会让边缘（高频）变形，所以要先按投影规律把关键地标（截止频率）预先挪一下位置（预畸变），投影后才落在正确的地方。`scipy.signal.butter` 内部就是"查模拟巴特沃斯原型 → 预畸变 → 双线性变换"三步——现在你知道它在干嘛了。

### 2.5 biquad 与参数 EQ：亲手推系数

终于到最实用的部分。你在 codec 里配的 EQ，底层几乎都是 **biquad（二阶节）**，差分方程：

$$
y[n] = \frac{b_0 x[n] + b_1 x[n-1] + b_2 x[n-2] - a_1 y[n-1] - a_2 y[n-2]}{a_0}
$$

（通常归一化让 `a₀=1`。5 个系数 `b₀,b₁,b₂,a₁,a₂` 就定义了一个 biquad。）

不同的系数组合，就是不同类型的 EQ。以最常用的**峰值均衡器 (peaking EQ**，在某频率提升/衰减一个包）为例，业界标准公式（来自 Robert Bristow-Johnson 的 Audio EQ Cookbook）：

先定义三个中间量（这就是你在 EQ 界面拖的三个旋钮）：
- `f0`：中心频率（"在哪提升"）
- `Q`：品质因数（"提升的包多窄"，Q 大则窄）
- `gain_dB`：增益（"提升/衰减多少 dB"）

$$
A = 10^{gain\_dB/40}, \quad \omega_0 = 2\pi f_0/f_s, \quad \alpha = \frac{\sin\omega_0}{2Q}
$$

则峰值 EQ 的系数为：

$$
\begin{aligned}
b_0 &= 1 + \alpha A, & b_1 &= -2\cos\omega_0, & b_2 &= 1 - \alpha A \\
a_0 &= 1 + \alpha/A, & a_1 &= -2\cos\omega_0, & a_2 &= 1 - \alpha/A
\end{aligned}
$$

**逐块拆解（这就是那些寄存器值的来源）：**
- `A` 由增益决定：提升时 `A>1`，衰减时 `A<1`。它出现在 `b`（分子，提升）和 `a`（分母，衰减）里，一升一降形成"包"。
- `ω₀` 由中心频率决定：`cos ω₀` 出现在 `b₁, a₁`，把"包"定位到 `f0`。
- `α` 综合了 `Q` 和 `ω₀`：控制包的宽窄。Q 越大 → α 越小 → 包越窄越尖。
- **这就是你在 EQ 界面拖动 f0/Q/gain 三个旋钮时，DSP 里实际发生的系数计算**。以前是黑盒，现在你能在 C 里从三个旋钮值算出 5 个系数，实现一个和 codec 里一样的参数 EQ。

> 🔧 **驱动直觉**：你配 codec 的 EQ 寄存器时，芯片手册给的往往就是"填 b0/b1/b2/a1/a2"或"填 f0/Q/gain 由硬件算"。现在你知道两者的换算了。而且回到第 04 篇：这个 biquad 的分母 `a` 提供极点、分子 `b` 提供零点——**峰值 EQ 就是在 f0 附近摆一对极点（提升）或零点（衰减）**。第 04 篇的零极点理论、第 07 篇的系数公式，在这里完全打通。

## 三、代码实战（重在看懂结果）

三个实验：从零手写窗函数法 FIR（不调 firwin）→ 亲手实现 biquad 参数 EQ 并验证频响 → 阶数估计的验证。依赖 `numpy`、`scipy`、`matplotlib`。

### 实验一：从零手写窗函数法 FIR——打开 firwin 的黑盒

不用 `scipy.firwin`，完全按 2.1+2.2 自己造一个低通，再和 scipy 对比，证明我们真的懂了。

```python
import numpy as np
from scipy import signal
import matplotlib.pyplot as plt

fs = 8000
fc = 1000        # 截止频率 1kHz
M = 81           # 阶数（选奇数，让群延迟(M-1)/2是整数）

# --- 第1步：理想低通的冲激响应 = sinc（2.1）---
n = np.arange(M)
center = (M-1)/2                          # 把sinc中心平移到这里(因果化)
# 归一化截止(数字频率)：fc对应的归一化 = 2*fc/fs
fc_norm = 2*fc/fs
# sinc定义（numpy的sinc已含π）：理想低通 h[n] = fc_norm * sinc(fc_norm*(n-center))
h_ideal = fc_norm * np.sinc(fc_norm * (n - center))

# --- 第2步：乘一个窗把无限sinc截短（2.2）。这里用Hamming ---
window = np.hamming(M)
h = h_ideal * window
h = h / np.sum(h)                          # 归一化，保证直流增益为1

# --- 对比scipy的firwin（它内部就是这套流程）---
h_scipy = signal.firwin(M, fc, fs=fs, window='hamming')
print("我的手写FIR 与 scipy.firwin 最大系数差异 =", np.max(np.abs(h - h_scipy)))

# --- 看频响（第03篇的 FFT(h)）---
w, H = signal.freqz(h, worN=2048, fs=fs)
_, H_rect = signal.freqz(h_ideal/np.sum(h_ideal), worN=2048, fs=fs)  # 矩形窗(不加窗)对比

plt.figure(figsize=(10,5))
plt.plot(w, 20*np.log10(np.abs(H_rect)+1e-9), alpha=0.5, label='rectangular (no window): big ripples')
plt.plot(w, 20*np.log10(np.abs(H)+1e-9), label='Hamming windowed: clean stopband')
plt.axvline(fc, color='k', ls='--'); plt.ylim(-80,5)
plt.xlabel('Hz'); plt.ylabel('|H| dB'); plt.legend(); plt.grid(True)
plt.title('Window-method FIR: how the window kills the ripples')
plt.tight_layout(); plt.show()
```

**运行结果：**
```
我的手写FIR 与 scipy.firwin 最大系数差异 = 3.x e-17
```

**结果解读（重点）：**

1. **"差异 3e-17"（浮点级）= 我们手写的和 scipy 完全一样**。你现在**彻底打开了 firwin 的黑盒**——它就是"sinc × 窗 + 归一化"。这套流程你能用 C 徒手实现，不再依赖任何库。

2. **两条频响曲线的对比是 2.2 的铁证**：
   - 矩形窗（不加窗，直接截断 sinc）：阻带里有一堆**大波纹**，最深只压到约 −21dB——高频漏得厉害。这就是第 03 篇实验三那个"波纹"的真身。
   - Hamming 窗：阻带干净地压到 −53dB 以下。**窗函数把波纹"抹平"了。**

3. **代价看得见**：仔细看 Hamming 曲线在截止频率 1kHz 附近的滚降，比矩形窗**更缓**（过渡带更宽）。这就是 2.2 说的"阻带衰减换过渡带宽度"的权衡——想要干净的阻带，就得接受更宽的过渡带（或堆更高的阶数）。

### 实验二：亲手实现参数 EQ（biquad）——造一个 codec 里的 EQ

用 2.5 的公式，从"f0/Q/gain 三个旋钮"算出 biquad 系数，验证频响真的在 f0 处提升了预期的 dB。

```python
import numpy as np
from scipy import signal
import matplotlib.pyplot as plt

def peaking_eq(f0, Q, gain_db, fs):
    """
    RBJ Audio EQ Cookbook 峰值均衡器系数（2.5的公式）。
    返回 (b, a) 可直接喂给 scipy.lfilter 或在C里实现。
    """
    A = 10**(gain_db/40)
    w0 = 2*np.pi*f0/fs
    alpha = np.sin(w0)/(2*Q)
    cos_w0 = np.cos(w0)
    # 分子(b)带A -> 提升；分母(a)带1/A -> 衰减
    b = [1 + alpha*A, -2*cos_w0, 1 - alpha*A]
    a = [1 + alpha/A, -2*cos_w0, 1 - alpha/A]
    b = np.array(b)/a[0]; a = np.array(a)/a[0]   # 归一化 a0=1
    return b, a

fs = 48000
# 三个不同的EQ设置，看Q和gain的作用
configs = [(3000, 2.0, 6, 'f0=3k Q=2 +6dB'),
           (3000, 5.0, 6, 'f0=3k Q=5 +6dB (narrower)'),
           (1000, 2.0, -9,'f0=1k Q=2 -9dB (cut)')]

plt.figure(figsize=(10,5))
for f0, Q, g, name in configs:
    b, a = peaking_eq(f0, Q, g, fs)
    w, H = signal.freqz(b, a, worN=4096, fs=fs)
    plt.semilogx(w, 20*np.log10(np.abs(H)+1e-9), label=name)
    # 验证：在f0处的实际增益
    idx = np.argmin(np.abs(w - f0))
    print(f"{name}: 在f0={f0}Hz处实测增益 = {20*np.log10(np.abs(H[idx])):+.2f} dB")
plt.axhline(0, color='k', lw=0.5); plt.xlim(100, 20000)
plt.xlabel('Hz (log)'); plt.ylabel('gain dB'); plt.legend(); plt.grid(True)
plt.title('Parametric EQ (biquad) hand-computed from f0/Q/gain')
plt.tight_layout(); plt.show()
```

**运行结果：**
```
f0=3k Q=2 +6dB: 在f0=3000Hz处实测增益 = +6.00 dB
f0=3k Q=5 +6dB (narrower): 在f0=3000Hz处实测增益 = +6.00 dB
f0=1k Q=2 -9dB (cut): 在f0=1000Hz处实测增益 = -9.00 dB
```

**结果解读：**

1. **实测增益精确命中设定值**（+6/+6/−9dB）：说明 2.5 那套公式是对的，我们从三个旋钮值算出的 5 个系数，造出的 EQ 精确实现了预期。**你现在有了一个可以直接搬进 C 代码、和 codec 里一样的参数 EQ 实现。**

2. **看图理解 Q 的作用**：`Q=2` 的包（蓝）和 `Q=5` 的包（橙）都在 3kHz 提升 6dB，但 **Q=5 的包明显更窄更尖**。这直观对应 2.5 里"Q 大 → α 小 → 包窄"。以后调 EQ 的 Q 旋钮，你知道它在数学上动了什么。

3. **提升与衰减的对称性**：−9dB 那条（绿）是一个向下的"坑"。对比公式——提升时 A 进分子，衰减时 1/A 进分母，结构对称，所以 EQ 能对称地提升或衰减。

### 实验三：验证阶数估计公式

快速验证 2.3 的经验公式：要求越苛刻，需要的阶数是否真的按预期增长。

```python
import numpy as np
from scipy import signal

fs = 8000
# 用 kaiserord 估计达到指定指标所需的阶数
for A_stop, trans_hz in [(40, 500), (60, 500), (60, 200)]:
    # A_stop:阻带衰减dB, trans_hz:过渡带宽Hz
    numtaps, beta = signal.kaiserord(A_stop, trans_hz/(fs/2))
    print(f"阻带衰减{A_stop}dB, 过渡带{trans_hz}Hz -> 需要 {numtaps} 阶FIR")
```

**运行结果（近似）：**
```
阻带衰减40dB, 过渡带500Hz -> 需要 23 阶FIR
阻带衰减60dB, 过渡带500Hz -> 需要 37 阶FIR
阻带衰减60dB, 过渡带200Hz -> 需要 91 阶FIR
```

**结果解读：**

1. **阻带从 40→60dB（要求更深）**：阶数 23→37，涨了约 60%。深度要求提高，成本上升。

2. **过渡带从 500→200Hz（要求更窄）**：阶数 37→91，涨了 1.5 倍。**过渡带变窄对阶数的影响比阻带更剧烈**（因为公式里 M ∝ 1/Δω）。

3. **工程含义直击 2.3**：这三行数字就是你和客户谈判的底牌。"过渡带再窄一倍，阶数要翻倍还多，延迟和算力都跟着翻"——**把模糊的"性能要求"变成精确的"资源成本"，这就是算法工程师的价值。**

## 四、驱动工程师视角：从"填寄存器"到"算寄存器"

| 概念 | 驱动工程师视角（你熟悉的） | 算法工程师视角 |
|------|--------------------------|--------------------------|
| **EQ 寄存器 b0/b1/b2/a1/a2** | codec 手册让你填的系数 | biquad 系数，由 f0/Q/gain 算出 |
| **f0/Q/gain 旋钮** | EQ 界面/寄存器字段 | 峰值 EQ 的三个物理参数 |
| **`scipy.firwin`** | 黑盒调用 | sinc × 窗 + 归一化 |
| **`scipy.butter`** | 黑盒调用 | 模拟原型 + 预畸变 + 双线性变换 |
| **滤波器阶数** | 影响算力/延迟的参数 | 由阻带/过渡带指标反算 |
| **FIR 群延迟 (M−1)/2** | latency 里的一项 | sinc 因果化平移的结果 |
| **高阶拆 biquad 级联** | 你见过的 DSP 代码 | 稳定性 + 模块化设计 |

**三个"原来如此"：**

1. **codec 里那些 EQ 寄存器值，你现在能自己算了。** 给你 f0=3k/Q=2/+6dB，你能用 2.5 的公式手算出 b0..a2，甚至在没有 scipy 的裸机 DSP 上用 C 实现。从"填厂商给的数"升级到"自己造数"。

2. **firwin/butter 不再是魔法。** FIR 是"sinc 截窗"，IIR 是"模拟原型数字化"。你理解了它们的内部，就能判断什么场景用哪个、参数怎么调、为什么会有波纹/过渡带/相位问题。

3. **FIR 那个 (M−1)/2 群延迟，来自 sinc 的因果化平移。** 第 04 篇你知道它"是个常数延迟"，这篇你知道它"为什么是这个值"——因为要把中心在 0 的对称 sinc 平移成因果的。

**最关键的一句话总结：**

> 滤波器设计，是"频域愿望"到"时域系数"的双向翻译工程。FIR 走"理想响应→截窗"的路，IIR 走"借用模拟原型→变换"的路，参数 EQ 则把这一切浓缩成三个直观旋钮背后的 5 个系数。
> 驱动侧你**填**系数、**加载**系数；算法侧你**设计**系数、**理解**系数为什么长这样。
> **当你能从一句"我要 3kHz 提升 6dB"直接写出 C 代码里的 5 个 biquad 系数时，你就真正跨过了从驱动到算法的这道坎——你不再需要那个黑盒了。**

## 五、与下一篇的衔接

到这里，我们对"确定性信号"和"LTI 系统"的处理已经相当完整：采样、卷积、频域、滤波器设计。但这套理论有一个隐含前提——**信号是确定的、可预测的**（一个正弦就是一个正弦）。

**现实却充满"随机性"**：麦克风底噪是随机的、环境噪声是随机的、语音本身在统计意义上也是随机过程。你没法写出噪声的确切公式 `x[n]=...`，只能描述它的**统计特性**（平均能量多大、频率分布如何、前后样本相关性怎样）。

**下一篇（第 08 篇《随机信号入门：自相关、互相关与功率谱密度》）**，我们迈出从"确定性信号处理"到"统计信号处理"的关键一步——而**这一步正是通向自适应滤波、降噪、AEC 的必经之门**。你会学到：
- **为什么真实信号必须用统计而非公式描述**；
- **自相关**：信号和自己的相似度——揭示周期性、区分噪声与信号；
- **互相关**：两个信号的相似度——**它会直接给出"回声延迟估计"的算法**，这正是 AEC 对齐参考信号的核心；
- **功率谱密度 (PSD)** 与**维纳-辛钦定理**：随机信号的"频谱"该怎么定义（不能直接 FFT！）。

第 08 篇之后，09（维纳滤波）→10（LMS）→11（RLS）会一路把自适应滤波推导到底，最终在第 13 篇 AEC 汇合。**进阶篇正在向核心声学算法收拢。**
