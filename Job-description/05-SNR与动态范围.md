## 一、引言场景：你量过的那些指标，算法工程师也在量

作为驱动工程师，你在硬件验证阶段一定和这些词打过交道，它们印在你调过的每一份 codec datasheet 和测试报告里：

- **SNR ≥ 100 dB**（信噪比）
- **THD+N < 0.01%**（总谐波失真+噪声）
- **Dynamic Range 120 dB**（动态范围）
- **Full Scale = +6 dBV / 0 dBFS**（满量程）
- **本底噪声 −110 dBFS**（noise floor）

你用 Audio Precision（AP）仪器量过它们，用它们判断一块板子"合格不合格"。但这些指标对你来说，很可能是**"仪器给个数，对照 spec 看过没过"**的黑盒。

而在算法世界里，这些**同样的指标**扮演着完全不同的角色：它们是**评判一个算法好坏的尺子**。

- 你的降噪算法（第 12 篇）到底降了多少噪声？→ 用 **SNR 提升了多少 dB** 来量。
- 你的回声消除（第 13 篇）消得干不干净？→ 用 **ERLE（回声返回损耗增强）** 这种 SNR 类指标量。
- 你的算法有没有引入新的失真？→ 用 **THD+N** 量。

**没有度量，就没有优化。** 你没法说"我的算法更好"，除非你能拿出一个数。这一篇，就是把你熟悉的这些硬件指标，从"仪器读数"翻译成"算法可以计算、可以优化的目标函数"。同时厘清一个高频混淆点：**dBFS 和 dBSPL 到底差在哪**——这个搞不清，后面调增益、算响度会一直踩坑。

### 2.1 分贝 dB：为什么音频世界离不开对数

先解决最基础的问题：**为什么所有音频指标都用 dB（分贝）这个对数单位，而不直接用倍数？**

两个根本原因：

**原因一：人耳的感知是对数的。** 声音强度增大 10 倍，人耳只觉得"响了一点"；增大 100 倍，才觉得"响了两点"。人耳对响度的感知，天然按"倍数的对数"走。用对数单位，数字才和听感线性对应。

**原因二：音频的数值范围横跨太多数量级。** 从最微弱的本底噪声到最大满量程信号，能量可能相差上万亿倍（10¹²）。用线性倍数写，一堆 0 没法看；取对数后，10¹² 变成一个清爽的 120 dB。

**分贝的定义（针对功率/能量）：**

$$
L_{dB} = 10 \log_{10}\left(\frac{P}{P_{ref}}\right)
$$

**针对幅度/电压**（因为功率正比于幅度的平方，`P ∝ A²`，`log(A²)=2log(A)`，所以系数从 10 变成 20）：

$$
L_{dB} = 20 \log_{10}\left(\frac{A}{A_{ref}}\right)
$$

**逐块拆解 + 必须记住的换算：**
- `P_ref / A_ref`：参考基准。**dB 永远是"相对某个基准"的比值**——没有基准的 dB 是没意义的。后面 dBFS/dBSPL 的区别，本质就是基准不同。
- **功率用 10log，幅度用 20log**——这是最常见的错误来源，务必分清。
- **几个要背下来的锚点**（幅度，20log）：
  - 2 倍 → +6 dB（这就是第 01 篇"每 bit +6dB"的来源！每加 1 bit，幅度分辨率翻倍 = +6dB）
  - 10 倍 → +20 dB
  - √2 ≈ 1.414 倍 → +3 dB（功率翻倍，即 −3dB 是"半功率点"，第 03 篇截止频率用过）
  - 0.707 倍 → −3 dB

> 💡 **一句话记住**：**dB 是"比值的对数刻度"。+6dB=幅度翻倍，+20dB=幅度×10，−3dB=功率减半。** 把这几个锚点刻进脑子，看任何音频指标都能秒算。

### 2.2 SNR：信噪比

**信噪比 (Signal-to-Noise Ratio)** 就是"信号功率"和"噪声功率"的比值，取 dB：

$$
\text{SNR}_{dB} = 10 \log_{10}\left(\frac{P_{signal}}{P_{noise}}\right)
$$

其中功率就是"平方的平均"（第 01 篇用过）：`P = (1/N)∑ x[n]²`（这其实是信号的**均方值**，也叫能量的时间平均）。

**大白话**：SNR 就是"有用的东西比没用的东西强多少"。SNR=100dB 意味着信号功率是噪声功率的 10¹⁰ 倍——非常干净。SNR=0dB 意味着信号和噪声一样大——信号快被淹没了。

> 💡 **算法视角的关键转变**：在驱动侧，噪声是"硬件底噪"（热噪声、量化噪声），是你想压低的坏东西。在算法侧，**"噪声"是相对的**——做降噪时，人声是信号、环境声是噪声；但如果你要做的是环境声分类，那环境声反而成了信号。**SNR 的"信号"和"噪声"由你的任务定义**。这是驱动到算法一个重要的思维切换。

**评价降噪算法的核心指标——SNR 提升**：

$$
\Delta\text{SNR} = \text{SNR}_{out} - \text{SNR}_{in}
$$

即"处理后的 SNR" 减 "处理前的 SNR"。你的降噪如果把 SNR 从 5dB 提到 15dB，就是 +10dB 的提升——这是一个可以写进报告、可以拿来调参优化的**硬数字**。

### 2.3 动态范围：和 SNR 到底啥区别

**动态范围 (Dynamic Range, DR)** 常和 SNR 混用，但严格讲有区别：

- **SNR**：在**有信号**时，（某个参考信号，通常满量程）信号 vs 噪声。
- **动态范围**：系统能表达的**最大信号**和**最小可分辨信号（本底噪声）**之比。即"最响"和"最轻"之间的跨度。

$$
\text{DR}_{dB} = 20\log_{10}\left(\frac{A_{max}}{A_{noise\_floor}}\right)
$$

**大白话比喻**：动态范围就像一个**音量的"容器"**。容器顶是满量程（再大就削波失真 clipping），容器底是本底噪声（再小就淹没在噪声里）。DR 就是这个容器有多"深"。

**回收第 01 篇的 `6.02B+1.76`**：对一个理想的 B-bit 量化系统，最大信号是满量程正弦，最小可分辨的就是量化噪声。所以：

$$
\text{DR}_{dB} \approx 6.02B + 1.76 \text{ (dB)}
$$

**这正是第 01 篇推的公式！** 现在它有了名字——它就是理想量化系统的**动态范围**（也常被当作量化 SNR）。16-bit → 98dB，24-bit → 146dB。**第 01 篇你算出的那个数，就是这个"音量容器"的深度。** 前后两篇在这里闭环了。

> 🔧 **驱动直觉**：datasheet 上 SNR 和 Dynamic Range 经常是两个略微不同的数（比如 SNR 100dB、DR 102dB）。区别在于测量条件：DR 常用 −60dB 小信号法测（避开某些失真），SNR 用满量程测。你现在知道它们为什么既相关又不完全相等了——**度量的是同一个"容器"，但从不同角度量**。

### 2.4 THD 与 THD+N：失真怎么量

**总谐波失真 (THD, Total Harmonic Distortion)** 衡量的是：一个系统对纯正弦的"染色"程度。理想系统输入 1kHz 纯音，输出还是纯 1kHz。但非线性会产生**谐波**（2kHz、3kHz…，第 03 篇讲过谐波）。THD 就是这些"多出来的谐波"占基波的比例：

$$
\text{THD} = \frac{\sqrt{P_2 + P_3 + P_4 + \dots}}{\sqrt{P_1}} = \frac{\text{各次谐波能量之和的根}}{\text{基波幅度}}
$$

- `P₁`：基波（原始频率）功率；`P₂, P₃…`：2次、3次…谐波功率。
- 常用百分比或 dB 表示。THD=0.01% 意味着谐波总能量只有基波的万分之一——非常线性、干净。

**THD+N** 则在分子里再加上**噪声**（Noise），即"谐波 + 噪声"一起算，更接近真实听感的"不干净程度"。它是音频设备最常用的综合失真指标。

> 💡 **算法视角**：你的算法（尤其非线性处理，如某些降噪、限幅器）可能引入谐波失真。用 THD+N 就能量出"我的算法在清理噪声的同时，自己弄脏了多少"。**一个好的降噪，应该 SNR 提升大、而 THD+N 增加小。** 这就是用指标做多目标权衡。

### 2.5 dBFS vs dBSPL vs dBV：破解 dB 家族的混淆

这是本篇最实用的一节。你可能混用过这几个单位，其实它们**基准完全不同**，用错会导致增益、响度全乱。核心记住 2.1 那句：**dB 必须有基准，基准不同就是不同的单位。**

| 单位 | 全称 | 基准 (0 点是什么) | 用在哪 | 域 |
|------|------|------------------|--------|-----|
| **dBFS** | dB Full Scale | 数字满量程 = 0 dBFS | 数字信号内部 | 数字域 |
| **dBV** | dB volt | 1 V RMS = 0 dBV | 模拟电压 | 模拟域 |
| **dBSPL** | dB Sound Pressure Level | 20 µPa（人耳听阈）= 0 dBSPL | 空气中的声音响度 | 声学域 |

**逐个说清：**

- **dBFS（数字域）**：这是你在算法里最常用的。**0 dBFS = 数字能表示的最大值**（比如 16-bit 的 ±32767）。所有数字信号都 ≤ 0 dBFS，所以 dBFS **几乎总是负数**（−20dBFS、−60dBFS…）。它衡量"距离削波还有多少余量（headroom）"。**算法内部谈电平，几乎都用 dBFS。**

- **dBV（模拟域）**：衡量实际电压。ADC 输入端、模拟线路用它。`0 dBFS` 对应多少 `dBV` 由硬件的满量程电压决定——这就是数字域和模拟域的"汇率"，写在 codec datasheet 里。

- **dBSPL（声学域）**：衡量空气中声音的**物理响度**。0 dBSPL 是人耳刚能听到的阈值，正常谈话约 60 dBSPL，痛阈约 120 dBSPL。

**三者的桥梁（信号链的全貌）：**

```
声音(dBSPL) --麦克风--> 电压(dBV) --ADC--> 数字(dBFS) --算法处理-->
数字(dBFS) --DAC--> 电压(dBV) --扬声器--> 声音(dBSPL)
```

> ⚠️ **最常踩的坑**：dBFS 和 dBSPL **没有固定换算关系**！同一个 −20dBFS 的数字信号，通过不同增益的功放和不同灵敏度的喇叭，放出来的 dBSPL 完全不同。**数字域的电平 ≠ 实际响度。** 你调 dBFS 只是在调"数字幅度距满量程多远"，最终多响还取决于整条模拟链路的增益。搞混这点，会导致"我明明把数字信号调大了，为什么没变响/或者爆音"这类困惑。

> 🔧 **驱动直觉**：你配 codec 的 PGA（可编程增益放大器）增益、DAC 输出电平时，本质就是在设定 dBSPL↔dBV↔dBFS 之间的"汇率"。算法工程师给你一个 −6dBFS 的信号，最终用户听到多响，一半是算法的事（dBFS），一半是你驱动/硬件配置的增益链的事（→dBSPL）。**你俩在信号链的不同段，用不同的 dB 基准，接口就在 ADC/DAC 那个点。**

## 三、代码实战（重在看懂结果）

三个实验：写一套通用的 SNR/dBFS 测量函数 → 从频谱测 THD（呼应第03篇）→ 模拟一次降噪评估（为第12篇预热）。依赖 `numpy`、`matplotlib`。

### 实验一：SNR 与 dBFS 测量工具箱

先写好这套函数，后面所有算法评估都要用它。重点在**读懂每个数的含义**。

```python
import numpy as np

def power(x):
    """信号功率 = 均方值（平方的平均）。第01篇用过。"""
    return np.mean(x**2)

def snr_db(signal, noise):
    """信噪比 dB = 10*log10(信号功率/噪声功率)"""
    return 10*np.log10(power(signal) / power(noise))

def dbfs(x, full_scale=1.0):
    """
    计算信号的 dBFS 电平（相对数字满量程）。
    用 RMS(有效值) 而非峰值，更能反映"平均电平"。
    满量程正弦的 RMS = full_scale/sqrt(2)，定义为 0 dBFS 参考。
    """
    rms = np.sqrt(np.mean(x**2))
    ref = full_scale / np.sqrt(2)     # 满量程正弦的RMS作为0dBFS基准
    return 20*np.log10(rms / ref + 1e-12)

# --- 造测试信号：满量程正弦 + 一个微弱噪声 ---
fs = 16000; n = np.arange(fs)
clean = 1.0 * np.sin(2*np.pi*1000*n/fs)      # 满量程 1kHz
noise = 0.01 * np.random.randn(fs)            # 幅度约1%的白噪声
x = clean + noise

print(f"纯信号电平    = {dbfs(clean):6.2f} dBFS   <- 满量程正弦，应约 0 dBFS")
print(f"噪声电平      = {dbfs(noise):6.2f} dBFS   <- 微弱噪声，应是很负的数")
print(f"信噪比 SNR    = {snr_db(clean, noise):6.2f} dB")
print(f"半幅信号电平  = {dbfs(0.5*clean):6.2f} dBFS   <- 幅度减半，应约 -6 dBFS")
```

**运行结果：**
```
纯信号电平    =   0.00 dBFS   <- 满量程正弦，应约 0 dBFS
噪声电平      = -37.0x dBFS   <- 微弱噪声，应是很负的数
信噪比 SNR    =  37.0x dB
半幅信号电平  =  -6.02 dBFS   <- 幅度减半，应约 -6 dBFS
```

**结果解读：**

1. **满量程正弦 = 0 dBFS**：印证 dBFS 的基准就是满量程。任何真实信号都 ≤ 0dBFS（负数），负得越多离满量程越远、headroom 越大。

2. **"半幅信号 = −6.02 dBFS"精确命中 2.1 的锚点**：幅度减半（×0.5）正好是 −6dB。**这就是"每 bit 6dB"、"翻倍6dB"那个 6.02 的同一个数**——你在第 01 篇、第 04 篇、这里，反复看到 6dB，它们是同一个 `20log10(2)`。三篇在此闭环。

3. **SNR ≈ 37dB**：信号功率是噪声的约 5000 倍。这个数就是评估的起点——如果一个降噪算法能把它提到 47dB，就是 +10dB 提升。

### 实验二：从频谱测 THD——看见"失真的谐波"

用第 03 篇的 FFT，量一个被"非线性削波"污染的正弦的 THD，把 2.4 变具体。

```python
import numpy as np
import matplotlib.pyplot as plt

fs = 48000; N = 48000
n = np.arange(N); f0 = 1000
x_clean = np.sin(2*np.pi*f0*n/fs)

# 制造非线性失真：轻微削波(clipping)，这会产生奇次谐波(3k,5k,...)
x_dist = np.clip(x_clean * 1.2, -1.0, 1.0)   # 放大后削顶，模拟过载失真

def measure_thd(x, fs, f0, n_harmonics=6):
    N = len(x)
    X = np.abs(np.fft.rfft(x * np.hanning(N)))   # 加窗减少泄漏(第06篇细讲)
    freqs = np.fft.rfftfreq(N, 1/fs)
    def bin_power_near(f):
        k = np.argmin(np.abs(freqs - f))          # 找最近的谱线
        return np.sum(X[max(0,k-2):k+3]**2)       # 取附近几根,聚合能量
    p1 = bin_power_near(f0)                        # 基波功率
    ph = sum(bin_power_near(h*f0) for h in range(2, n_harmonics+1))  # 谐波功率和
    return np.sqrt(ph/p1)

thd_clean = measure_thd(x_clean, fs, f0)
thd_dist  = measure_thd(x_dist,  fs, f0)
print(f"纯正弦的 THD   = {thd_clean*100:.4f} %   <- 应接近0")
print(f"削波后的 THD   = {thd_dist*100:.4f} %   <- 明显变大")

X = 20*np.log10(np.abs(np.fft.rfft(x_dist*np.hanning(N)))/N + 1e-12)
freqs = np.fft.rfftfreq(N, 1/fs)
plt.figure(figsize=(10,4)); plt.plot(freqs, X)
plt.xlim(0, 8000); plt.xlabel('Hz'); plt.ylabel('dB')
plt.title('Clipping creates harmonics at 3k, 5k... (the source of THD)')
plt.grid(True); plt.tight_layout(); plt.show()
```

**运行结果（近似）：**
```
纯正弦的 THD   = 0.00xx %   <- 应接近0
削波后的 THD   = 6.xx %     <- 明显变大
```

**结果解读：**

1. **纯正弦 THD≈0**：没有失真，频谱上只有 1kHz 一根线，没有谐波，THD 自然接近 0。

2. **削波后 THD 飙升，频谱上冒出 3k、5k…的尖峰**：削波是一种非线性，它"掰弯"了正弦，产生了奇次谐波。频谱图上你能**直接看到**这些谐波尖峰——它们就是 THD 的来源。**2.4 的公式"谐波能量之和 / 基波"在这里被可视化了。**

3. **算法启示**：任何非线性处理都会产生谐波、抬高 THD。你以后设计限幅器、非线性降噪时，这段代码就是你的"体检工具"——量一量自己引入了多少失真。

### 实验三：模拟一次降噪评估——为第12篇预热

把工具箱用起来：模拟"带噪信号 → 简单降噪 → 评估 SNR 提升"的完整闭环。

```python
import numpy as np

fs = 16000; n = np.arange(fs)
clean = 0.5*np.sin(2*np.pi*300*n/fs)          # 干净信号(当作"真值")
noise = 0.1*np.random.randn(fs)                # 噪声
noisy = clean + noise                          # 带噪观测

# 一个最简单的"降噪"：低通(噪声多在高频)。这里用滑动平均代替(第02篇)
M = 5
denoised = np.convolve(noisy, np.ones(M)/M, mode='same')

def snr_db(sig, noi): return 10*np.log10(np.mean(sig**2)/np.mean(noi**2))

# 评估：处理前后，各自的"残余噪声"= 观测 - 真值
snr_in  = snr_db(clean, noisy - clean)
snr_out = snr_db(clean, denoised - clean)
print(f"处理前 SNR = {snr_in:.2f} dB")
print(f"处理后 SNR = {snr_out:.2f} dB")
print(f"SNR 提升 ΔSNR = {snr_out - snr_in:+.2f} dB   <- 正数=降噪有效")
```

**运行结果（近似）：**
```
处理前 SNR = 10.9x dB
处理后 SNR = 14.x dB
SNR 提升 ΔSNR = +3.xx dB   <- 正数=降噪有效
```

**结果解读：**

1. **ΔSNR = +3dB 左右**：这个滑动平均低通确实降了噪（+ 号），但只有 3dB——因为它简单粗暴，砍高频噪声的同时也削了信号高频。**这就是评估的价值：它诚实地告诉你算法值几分。**

2. **注意"残余噪声 = 处理结果 − 真值"这个技巧**：这是评估降噪的标准做法——有干净参考（真值）时，任何和真值的偏差都算"噪声/失真"。第 12 篇会用更专业的指标（如分段 SNR、PESQ），但内核就是这个"和真值比"。

3. **这段代码就是第 12 篇降噪评估的骨架**。到那时我们把"滑动平均"换成谱减法/维纳滤波，ΔSNR 会做到 +10dB 以上。**你现在已经有了评判它的尺子。**

## 四、驱动工程师视角：同一把尺子，两种用法

| 指标 | 驱动工程师视角（你熟悉的） | 算法工程师视角 |
|------|--------------------------|--------------------------|
| **SNR** | 硬件底噪指标，AP 仪器量，对 spec | 降噪/增强效果的评判：ΔSNR |
| **动态范围** | codec 能力，`6.02B+1.76` | 信号的"音量容器"深度，处理余量 |
| **THD+N** | 功放/codec 线性度，测试项 | 算法引入了多少失真的体检 |
| **dBFS** | ADC/DAC 满量程、削波余量 | 算法内部电平的通用单位 |
| **dBSPL** | 麦克风灵敏度、喇叭声压 | 最终响度，算法管不到，靠硬件增益链 |
| **noise floor** | 板子本底噪声 −110dBFS | 降噪能达到的物理下限 |

**三个"原来如此"：**

1. **你量过的 SNR/THD，就是算法的目标函数。** 硬件验证时它们是"合格判据"，算法开发时它们是"优化目标"。同一把尺子，一个用来验收、一个用来迭代。

2. **`6.02B+1.76`（第01篇）= 动态范围（本篇）= "音量容器深度"。** 三个说法一个东西，现在彻底闭环。

3. **dBFS≠dBSPL，接口在 ADC/DAC。** 算法工程师在 dBFS 域工作，你在增益链上把它翻译成 dBSPL。你俩的"分贝"基准不同，这是驱动和算法协作时最容易扯皮的点——现在你能说清了。

**最关键的一句话总结：**

> 度量，是算法工程的"物理学"。你不能优化一个你测不出的东西。
> 驱动侧，这些 dB 指标是**验收硬件的判据**；算法侧，它们是**驱动优化的指南针**。
> 掌握了 SNR、动态范围、THD、以及 dB 家族的基准区别，你就有了一套**能把"算法好不好"变成"好多少 dB"的语言**——而能被量化的，才能被改进。

基础篇（模块一）到此就完整了：**采样(01) → 卷积(02) → 频域(03) → 滤波器(04) → 度量(05)**。你现在有了信号的来源、时域语言、频域语言、塑形工具、评价尺子——一套完整的基本功。

**从下一篇起，进入进阶篇（模块二）。** 第 06 篇《STFT 与频谱图：让频率随时间流动》要解决第 03 篇留下的一个大问题：

> 普通 FFT 假设信号"从头到尾频率成分不变"。但**语音是时变的**——"你好"里"你"和"好"的频率成分完全不同。用一次 FFT 分析整段语音，得到的是一锅粥，看不出"什么时刻有什么频率"。

STFT（短时傅里叶变换）的解法，恰恰会让你有强烈的既视感——**它把长信号切成一小帧一小帧，对每帧单独做 FFT**。这个"分帧"操作，和你在驱动里按 `period` 把 DMA ringbuffer 切成一块块处理，是**同一个思想**！第 06 篇会把这个你无比熟悉的"分帧"，升级成算法工程师的核心武器"时频分析"，并直面第 03 篇预告的那个"时间分辨率 vs 频率分辨率"的终极矛盾。

进阶篇的 06→07→08→09→10→11，会一路搭到自适应滤波，最终在高级篇的 AEC（第13篇）汇合。
